Wakula 后续开发快速上手
======================

一、当前边界
----------
已完成：SLAM Toolbox、Nav2、OpenCV 轻量障碍证据、点云地形分类、带完整安全字段的
时间同步融合、保守速度门、传感器 profile、rosbag 离线评估、测试和 CI。

未完成且暂不开发：Gazebo、厂家 SDK、ros2_control、状态估计、FK/IK、动力学、站立步态、
关节控制、真正越障 Action、比赛流程。STEP/CLIMB 只识别并停车。

二、新电脑完整复现
----------------
系统：Ubuntu 24.04 amd64/arm64；ROS 2 Jazzy Desktop。先按 ROS 官方说明配置 apt 源，
再执行：

  sudo apt update
  sudo apt install -y git build-essential python3-pip python3-rosdep \
    python3-colcon-common-extensions python3-opencv \
    ros-jazzy-desktop ros-jazzy-slam-toolbox ros-jazzy-navigation2 \
    ros-jazzy-nav2-bringup ros-jazzy-cv-bridge ros-jazzy-tf2-sensor-msgs \
    ros-jazzy-pointcloud-to-laserscan ros-jazzy-robot-state-publisher \
    ros-jazzy-xacro ros-jazzy-rviz2 ros-jazzy-rosbag2

首次使用 rosdep：

  sudo rosdep init        # 如果提示 already initialized 可忽略
  rosdep update

获取并构建：

  git clone <仓库地址> ~/wakula
  cd ~/wakula
  source /opt/ros/jazzy/setup.bash
  rosdep install --from-paths src --ignore-src -r -y
  ./scripts/build.sh
  source install/setup.bash

建议把下行加入 ~/.bashrc（路径不同请修改）：

  source /opt/ros/jazzy/setup.bash
  source ~/wakula/install/setup.bash

VS Code：安装 Visual Studio Code 后，打开 ~/wakula。建议 Python、Pylance、C/C++、
CMake Tools、XML、YAML、ROS 插件；项目已有 .vscode/settings.json 和 tasks.json。

三、启动前必须由外部提供
--------------------
最低导航输入：
  /scan      sensor_msgs/msg/LaserScan
  /odom      nav_msgs/msg/Odometry
  odom -> base_link TF

SLAM 产生 map -> odom。启用地形感知还需：
  RGB Image
  PointCloud2（x/y/z，米）
  base_link 到传感器 frame 的 TF

当前仓库不会生成真实里程计或驱动电机。

四、常用启动命令
--------------
完整栈：

  cd ~/wakula
  source /opt/ros/jazzy/setup.bash
  source install/setup.bash
  ros2 launch slam slam.launch.py

无相机：

  ros2 launch slam slam.launch.py vision:=false

无 RViz：

  ros2 launch slam slam.launch.py rviz:=false

回放 bag：

  ros2 launch slam slam.launch.py use_sim_time:=true
  ros2 bag play <bag目录> --clock

设备 profile：

  ros2 launch slam slam.launch.py sensor_profile:=orbbec_gemini2

自定义话题：

  ros2 launch slam slam.launch.py \
    scan_topic:=/lidar/scan odom_topic:=/localization/odom \
    camera_topic:=/camera/color/image_raw point_cloud_topic:=/camera/depth/points

只启动感知与速度门，不启动 SLAM/Nav2：

  ros2 launch quadruped_bringup bringup.launch.py

五、快速验收
----------
  ros2 topic hz /scan
  ros2 topic hz /odom
  ros2 topic hz /terrain/features_stamped
  ros2 topic hz /vision/obstacle_stamped
  ros2 topic echo /crossing/mode
  ros2 topic echo /crossing/speed_scale
  ros2 run tf2_ros tf2_echo base_link <点云frame>
  ros2 run tf2_ros tf2_echo map base_link
  ./scripts/diagnose.sh

正常现象：vision=true 时没有同步的相机—点云消息会保持 speed_scale=0；识别 CLEAR 且
数据持续新鲜后为 1；STEP/CLIMB/PIT/WALL/BAR 为 0；相机证据只能在 WALK 时减速，
不能触发腿部动作。只有点云时使用 vision:=false，决策会自动采用兼容路径。

六、录包与离线评估
----------------
  ./scripts/record_bag.sh
  ros2 bag info bags/<bag名>
  ros2 run quadruped_tools perception_bag_evaluator --help

每种障碍至少采集不同距离、角度、速度、明暗、逆光和背景；还要采集大量无障碍负样本。
标签必须对应传感器时间，不要按观看视频的电脑时间粗略对齐。优先降低坑洞/高墙漏检，
再优化普通类别误报。

七、开发与提交检查
----------------
  ./scripts/build.sh
  source install/setup.bash
  colcon test
  colcon test-result --verbose
  git status --short
  git diff --check

修改算法时同步更新 README.md、instruction.txt、connect.txt、quickstart.txt。新增通信接口先
更新 connect.txt；改变参数或流程更新 instruction.txt；新增启动方式更新 quickstart.txt。

八、真机出来后的接入顺序
--------------------
1. 测量传感器安装位姿并修正 URDF/静态 TF。
2. 启动传感器驱动，通过 profile/remap 对齐 Image、PointCloud2 和 LaserScan。
3. 接入可靠 `/odom` 与 odom->base_link，只验证 SLAM 和 Nav2，不连接电机速度。
4. 录真实 bag，重调点云与 OpenCV，完成准确率统计。
5. 单独开发硬件驱动、状态估计、运动学、步态和安全层，并在台架验证。
6. 底盘能安全消费 `/cmd_vel` 后低速接入 Nav2。
7. 最后才设计真机越障控制与 Nav2 切换；不得把当前文字 action 当作控制命令。

九、RK3588 建议
-------------
保持 OpenCV 路径，不启用 YOLO；图像宽度 640、处理 8 Hz，点云处理 10 Hz 并限制最大点数。
确认 CPU/内存余量后再提高分辨率或频率。优先让相机/雷达驱动在硬件侧完成对齐、降采样
和滤波，避免同一份点云被多个节点重复转换。
