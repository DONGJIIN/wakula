Wakula 后续开发快速上手指南
===========================

用途
----

本文件面向第一次接手 Wakula 的开发者，目标是在十分钟内完成环境确认、编译测试、
启动软件，并快速了解当前成果、未完成部分和推荐开发顺序。

配套文档：

  README.md        项目首页、文档导航、当前状态、待办、安装和总体架构
  instruction.txt 模块职责、算法原理和调试方法
  connect.txt      Topic、Action、Service、TF、QoS 和接口字段
  quickstart.txt   本文件，跨电脑复现、快速接手、当前进度和后续路线


一、项目当前定位
----------------

系统环境：

  Ubuntu 24.04
  ROS 2 Jazzy
  Python 3
  目标计算平台 RK3588
  通用 12 自由度四足模型

核心软件：

  SLAM Toolbox              陌生环境二维建图与定位
  Nav2                      全局路径和局部避障
  OpenCV                    颜色、边缘和轮廓障碍提示
  PointCloud2               高度、坡度、粗糙度和近场立体障碍
  obstacle crossing manager 越障模式与速度倍率决策
  Collision Monitor         最终速度碰撞保护

当前已经形成完整的上层链路：

  建图定位
    -> 路径规划
    -> RGB 障碍提示
    -> 深度点云测高
    -> WALK/STEP/CLIMB/STOP
    -> 速度心跳保护
    -> /cmd_vel

尚未包含具体品牌机器狗 SDK、真实电机控制、MPC/WBC、完整落脚点规划和经过真机标定
的传感器参数。因此当前工程适合软件联调、算法验证和 SDK 接入开发，不能直接用于
未经保护的高速实机。


二、第一次接手的十分钟流程
--------------------------

1. 进入工作空间：

  cd ~/wakula

2. 查看 Git 状态和最近提交：

  git status -sb
  git log --oneline -5

正常情况下应位于 main，且没有未提交文件。

3. 加载 ROS 2：

  source /opt/ros/jazzy/setup.bash

4. 首次运行时安装依赖：

  ./scripts/bootstrap.sh

5. 编译全部 6 个 ROS 包：

  ./scripts/build.sh

6. 加载本工作空间：

  source install/setup.bash

每次打开新终端都需要重新 source ROS 2 和 install/setup.bash。

7. 运行测试：

  colcon test --event-handlers console_direct+
  colcon test-result --verbose

当前基准为 17 项测试、0 error、0 failure。

8. 查看机器人模型：

  ros2 launch quadruped_description display.launch.py

9. 无传感器启动完整软件：

  ros2 launch slam slam.launch.py rviz:=false

没有 /scan、/odom 和 map -> base_link 时，Nav2 应保持未激活并输出等待信息。这是安全
设计，不是错误。按一次 Ctrl+C，所有节点应正常退出。

10. 根据任务阅读文档：

  要启动系统或了解目录：README.md
  要修改算法：instruction.txt
  要接相机、雷达、SDK 或新节点：connect.txt
  要选择下一项开发任务：quickstart.txt


三、在另一台电脑完整复现
------------------------

以下步骤用于全新电脑或重新安装后的 RK3588。推荐严格使用 Ubuntu 24.04 LTS 64 位和
ROS 2 Jazzy；支持 amd64 与 arm64。不要复制 build、install、log，应克隆源码并在目标
电脑重新编译。建议至少 4 核 CPU、8 GB 内存和 20 GB 可用空间；无界面运行时可不启动 RViz。

3.1 需要准备的全部类别

必需：

  Ubuntu 24.04 LTS 64 位（UTF-8 locale）
  ROS 2 Jazzy Desktop、ros-dev-tools、rosdep、colcon
  Git、C/C++ 编译工具、CMake、Python 3.12
  Nav2、SLAM Toolbox、ros2_control、OpenCV、cv_bridge
  本仓库源码和各 package.xml 声明的 ROS/Python 依赖

开发电脑推荐：

  Visual Studio Code
  Python、Pylance、CMake Tools、C/C++、Remote SSH、XML 六个插件
  RViz、rqt_image_view、tf2_tools 等可视化调试工具

真机另需：

  2D 雷达、相机、机器狗 SDK 对应的 ROS 2 Jazzy 驱动或适配节点
  对应设备的 udev 规则、USB/串口权限和标定文件
  /scan、/odom、TF、标准 Image/PointCloud2 以及 /cmd_vel SDK 桥接
  多机运行时一致的 ROS_DOMAIN_ID、网络组播条件和系统时钟

本项目不需要 PyTorch、CUDA、TensorRT、神经网络模型或其他推理运行时。

3.2 安装 Ubuntu 基础工具并配置 ROS 软件源

先确认系统：

  lsb_release -a
  uname -m
  locale

按 ROS 2 官方方式配置 UTF-8、Universe 和 ROS apt 软件源：

  sudo apt update
  sudo apt install -y locales software-properties-common curl
  sudo locale-gen en_US en_US.UTF-8
  sudo update-locale LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8
  export LANG=en_US.UTF-8
  sudo add-apt-repository universe
  export ROS_APT_SOURCE_VERSION=$(curl -s https://api.github.com/repos/ros-infrastructure/ros-apt-source/releases/latest | grep -F "tag_name" | awk -F'"' '{print $4}')
  curl -L -o /tmp/ros2-apt-source.deb "https://github.com/ros-infrastructure/ros-apt-source/releases/download/${ROS_APT_SOURCE_VERSION}/ros2-apt-source_${ROS_APT_SOURCE_VERSION}.$(. /etc/os-release && echo ${UBUNTU_CODENAME:-${VERSION_CODENAME}})_all.deb"
  sudo dpkg -i /tmp/ros2-apt-source.deb
  sudo apt update

官方参考：
  https://docs.ros.org/en/jazzy/Installation/Ubuntu-Install-Debs.html

3.3 安装 ROS 2、编译工具和项目运行依赖

  sudo apt install -y \
    ros-jazzy-desktop ros-dev-tools \
    git build-essential cmake \
    python3-pip python3-venv python3-rosdep \
    python3-colcon-common-extensions python3-yaml \
    python3-numpy python3-opencv \
    ros-jazzy-navigation2 ros-jazzy-nav2-bringup \
    ros-jazzy-slam-toolbox \
    ros-jazzy-ros2-control ros-jazzy-ros2-controllers \
    ros-jazzy-joint-state-publisher-gui \
    ros-jazzy-robot-state-publisher ros-jazzy-xacro \
    ros-jazzy-cv-bridge ros-jazzy-sensor-msgs-py \
    ros-jazzy-tf2-sensor-msgs ros-jazzy-tf2-tools \
    ros-jazzy-rqt-image-view

只有驱动输出压缩图像或只有 3D 点云需要生成二维扫描时，再安装转换工具：

  sudo apt install -y \
    ros-jazzy-image-transport-plugins \
    ros-jazzy-pointcloud-to-laserscan

每台电脑只需初始化 rosdep 一次；若提示已初始化可继续：

  sudo rosdep init
  rosdep update

不要用 Conda 的 Python 运行 apt 安装的 ROS 2；本项目统一使用 /usr/bin/python3，避免
cv_bridge 与 ROS 二进制包 ABI 不匹配。第三方 Python 库应优先写入 package.xml 并由
rosdep 安装，不要随意 sudo pip install。

3.4 安装 VS Code 和仓库推荐插件

从 https://code.visualstudio.com/download 下载 Ubuntu 对应的 .deb（amd64 或 arm64），
在下载目录执行：

  sudo apt install ./code_*.deb

确认 code --version 可用后，安装本仓库全部推荐插件：

  code --install-extension ms-python.python
  code --install-extension ms-python.vscode-pylance
  code --install-extension ms-vscode.cmake-tools
  code --install-extension ms-vscode.cpptools
  code --install-extension ms-vscode-remote.remote-ssh
  code --install-extension redhat.vscode-xml

克隆后用 code ~/wakula 打开根目录，VS Code 也会读取 .vscode/extensions.json 提示安装。
.vscode/settings.json 使用 ${workspaceFolder}，因此用户名或克隆位置不同也无需改路径。
Remote SSH 仅在开发电脑远程连接 RK3588 时需要；其余插件用于 Python/C++、CMake 和
URDF/Xacro 编辑。VS Code 不是机器人运行时依赖。

3.5 配置 Git、克隆代码并锁定版本

  git config --global user.name "你的名字"
  git config --global user.email "你的邮箱"
  git clone https://github.com/DONGJIIN/wakula.git ~/wakula
  cd ~/wakula
  git switch main
  git pull --ff-only origin main

要精确复现实验版本，应在原电脑记录 git rev-parse HEAD，在新电脑执行：

  git checkout <记录的提交哈希>

只拉取公开仓库不需要 GitHub 登录。提交或推送需要配置 GitHub HTTPS token、SSH key
或 GitHub CLI 登录；这不是运行工程的必要条件。

3.6 解析源码依赖、编译和测试

  cd ~/wakula
  source /opt/ros/jazzy/setup.bash
  ./scripts/bootstrap.sh
  ./scripts/build.sh
  source install/setup.bash
  colcon test --event-handlers console_direct+
  colcon test-result --verbose

bootstrap.sh 会读取 6 个 package.xml，并用 rosdep 补齐遗漏依赖，因此 package.xml 是
最终依赖清单，上面的 apt 列表是可直接安装的完整基线。检查：

  ros2 pkg prefix quadruped_description
  ros2 pkg prefix quadruped_perception
  ros2 pkg prefix quadruped_planning
  ros2 pkg prefix slam
  python3 -c "import cv2, numpy; print(cv2.__version__)"

每个新终端都执行：

  source /opt/ros/jazzy/setup.bash
  cd ~/wakula
  source install/setup.bash

可选地把 source 写入 ~/.bashrc，但同时维护多个 ROS 发行版时不建议自动 source。

3.7 相机、雷达和机器狗硬件依赖

不存在适用于所有硬件的通用驱动。必须按设备厂商说明安装与 ROS 2 Jazzy、CPU 架构
匹配的驱动；若厂商只提供源码，将驱动放在单独工作空间编译，再先 source 驱动工作空间，
最后 source ~/wakula/install/setup.bash。不要把厂商 SDK 二进制和密钥提交到本仓库。

接入时至少满足：

  2D 雷达       发布 /scan，sensor_msgs/msg/LaserScan
  状态估计器    发布 /odom 和 odom -> base_link
  RGB 相机       发布标准 sensor_msgs/msg/Image
  深度/3D 雷达  发布含 x/y/z 的 sensor_msgs/msg/PointCloud2
  传感器外参    发布传感器 frame -> base_link TF
  SDK 适配器    订阅 /cmd_vel、/crossing/mode、/crossing/action

串口或 USB 设备常见权限配置：

  sudo usermod -aG dialout $USER

然后注销并重新登录，并安装厂商提供的 udev 规则。相机内参、雷达/相机外参、关节零位、
IMU、里程计尺度和时间同步参数必须在真机重新标定，不能照搬另一台机器的数值。

更换雷达或相机的最快流程：

1. 启动厂商 ROS 2 Jazzy 驱动，用 ros2 topic list -t 查看实际名称和类型。
2. 确认 2D 雷达为 LaserScan、RGB 为 Image、点云为 PointCloud2、里程计为 Odometry。
3. 用 ros2 topic echo <话题> --once 检查 header.frame_id 和时间戳。
4. 确认传感器 frame 到 base_link 的 TF；相机同时保留标准 CameraInfo。
5. 先从最接近的 profile 启动，例如：

  ros2 launch slam sensor_compat.launch.py sensor_profile:=realsense_d400

6. 如果驱动名称不同，只覆盖实际项：

  ros2 launch slam sensor_compat.launch.py \
    sensor_profile:=realsense_d400 \
    scan_topic:=/front_lidar/scan \
    odom_topic:=/robot/odometry \
    camera_topic:=/rgb/image_raw \
    point_cloud_topic:=/depth/points

7. 在 RViz 检查激光、点云与机器人重合，再做低速测试。

可用 profile：

  2D 雷达  ros_default rplidar ydlidar ldlidar hokuyo
  RGB-D    realsense_d400 orbbec_gemini2 zed2 oak_d
  3D 雷达  velodyne ouster livox hesai robosense lslidar

配置位于 src/slam/config/sensor_profiles.yaml。新增型号只需复制一个 profile 并填写
scan_topic、odom_topic、camera_topic、point_cloud_topic，不修改算法代码。profile 只是
常见起点，最终以驱动实际输出为准。厂商自定义消息必须先转换为 ROS 标准消息；3D 雷达
用于二维 SLAM 时还需生成 LaserScan。

3.8 两台电脑或开发电脑 + RK3588 联机

两端必须使用同一 ROS 2 发行版、相同 ROS_DOMAIN_ID，并允许 DDS UDP/组播通过网络：

  export ROS_DOMAIN_ID=24
  export ROS_LOCALHOST_ONLY=0

两端使用 chrony、NTP 或局域网时钟源同步系统时间。默认 RMW 为 Fast DDS；若修改
RMW_IMPLEMENTATION，两端应安装并使用相同实现。校园网、访客 Wi-Fi、VPN 和防火墙
常会阻止组播，优先使用同一路由器或有线局域网。用以下命令验收：

  ros2 node list
  ros2 topic list -t
  ros2 topic hz /scan
  ros2 topic echo /odom --once

3.9 无硬件复现和最终验收

没有传感器也能验证安装、模型和安全等待行为：

  ros2 launch quadruped_description display.launch.py
  ros2 launch slam slam.launch.py rviz:=false

第二条命令在没有 /scan、/odom、map -> base_link 时应等待而不激活 Nav2。最终验收：

  [ ] git status -sb 显示目标提交且工作区干净
  [ ] ./scripts/build.sh 成功
  [ ] colcon test-result --verbose 为 0 error、0 failure
  [ ] URDF 能在 RViz 打开
  [ ] 无传感器时 Nav2 安全等待，Ctrl+C 正常退出
  [ ] 真机 /scan、/odom、Image、PointCloud2 和 TF 频率稳定
  [ ] RViz 中点云、激光、机器人模型坐标重合
  [ ] /cmd_vel 只有 Collision Monitor 一个最终发布者
  [ ] 断传感器或决策超时后输出零速度

五、常用启动命令
----------------

每个新终端先执行：

  source /opt/ros/jazzy/setup.bash
  cd ~/wakula
  source install/setup.bash

只查看 URDF：

  ros2 launch quadruped_description display.launch.py

启动感知、越障决策和速度门，不启动 SLAM/Nav2：

  ros2 launch quadruped_bringup bringup.launch.py use_control:=false

启动完整自主链路：

  ros2 launch slam slam.launch.py

不启动 RViz：

  ros2 launch slam slam.launch.py rviz:=false

没有 RGB 相机时关闭 OpenCV：

  ros2 launch slam slam.launch.py vision:=false

指定非默认相机话题：

  ros2 launch slam slam.launch.py \
    camera_topic:=/my_camera/image_raw \
    point_cloud_topic:=/my_camera/points

使用常见相机/雷达 profile：

  ros2 launch slam sensor_compat.launch.py sensor_profile:=realsense_d400

任意非默认驱动话题：

  ros2 launch slam sensor_compat.launch.py scan_topic:=/front/scan \
    odom_topic:=/robot/odometry camera_topic:=/rgb/image_raw \
    point_cloud_topic:=/depth/points

加载 Nav2 但不自动激活：

  ros2 launch slam slam.launch.py rviz:=false nav2_autostart:=false

Robocon 比赛模式：

  ros2 launch slam slam.launch.py competition:=true

启用 mock ros2_control：

  ros2 launch quadruped_bringup bringup.launch.py use_control:=true


六、真机启动前必须提供的数据
----------------------------

基础导航：

  /scan                  sensor_msgs/msg/LaserScan
  /odom                  nav_msgs/msg/Odometry
  odom -> base_link      状态估计器 TF
  base_link -> lidar     URDF 或驱动静态 TF

SLAM Toolbox 根据 /scan、/odom 和 TF 产生 map -> odom。

视觉辅助：

  /camera/image_raw，或 connect.txt 中记录的其他候选 Image 话题。

点云地形：

  /camera/depth/points，或其他候选 PointCloud2 话题；
  点云 header.frame_id 到 base_link 的 TF。

机器狗执行层：

  订阅 /cmd_vel
  订阅 /crossing/mode
  订阅 /crossing/action
  在驱动侧实现命令超时、急停、姿态保护和关节限位

缺少点云时普通越障管理器保持 STOP，缺少导航传感器时 Nav2 保持未激活，均属于预期
的失效安全行为。


七、已经完成的工作
------------------

机器人模型和控制：

1. 通用 12 自由度四足 URDF/Xacro。
2. IMU、2D 雷达、RGB-D 相机坐标系。
3. mock ros2_control、关节状态和轨迹控制器。
4. RViz 模型调试入口。

SLAM 和 Nav2：

1. SLAM Toolbox 在线异步建图。
2. Nav2 全局规划、DWB 局部控制、恢复行为和行为树导航。
3. 精简启动文件，删除未使用的路由和停靠节点。
4. 固定速度链：cmd_vel_nav -> smoothed -> terrain_safe -> cmd_vel。
5. Collision Monitor 是 /cmd_vel 唯一最终发布者。
6. 雷达、里程计和定位 TF 就绪后才激活 Nav2。
7. 无传感器启动和关闭不再触发 Nav2 生命周期崩溃。

OpenCV：

1. HSV 橙色/蓝色分割。
2. Gaussian Blur、Canny 和轮廓几何识别。
3. poles、height_bar、wall、colored_obstacle 四类证据。
4. 最近 5 帧至少 3 帧一致的稳定判断。
5. 默认 8 Hz、最大 640 像素宽，适合 RK3588。
6. 默认图像话题锁定，源失联后自动切换。

点云：

1. 自动接入常见 PointCloud2 话题。
2. 按消息时间戳转换到 base_link。
3. NumPy 有限值过滤、ROI 裁剪和有界降采样。
4. 分位数地面/障碍高度估计。
5. 最小二乘坡度、粗糙度和可通行度估计。
6. 同一份 ROI 点云进入 Nav2 local_costmap。
7. 点云源锁定和失联自动切换。

融合和安全：

1. 点云决定 WALK、STEP、CLIMB、STOP。
2. OpenCV 只让 WALK 减速并等待深度确认。
3. 高度阈值和视觉证据合法性检查。
4. 导航命令和越障决策双心跳速度保护。
5. Python 节点重复 SIGINT 清理保护。
6. 合成 RGB + PointCloud2 端到端融合验证。

比赛框架：

1. Robocon V1.0 的 210 秒状态机。
2. 障碍提示、完成、失败、重试、计分和返回启动区。
3. 足端接触、有效距离、T 字台阶进度检查。

工程状态：

九、推荐后续开发路线
--------------------

阶段 0：冻结整机需求和系统方案

1. 明确尺寸、重量、自由度、速度、续航、载荷、越障指标、预算和比赛规则。
2. 完成机械、电气、控制、计算、传感器和通信框图，分配安全责任与接口负责人。
3. 根据峰值关节扭矩、速度和冲击载荷完成执行器及电池初步选型。

阶段交付：需求规格书、系统框图、接口清单、BOM/预算和风险清单。
通过条件：指标全部可测量，关键部件选型有计算依据，整机接口和负责人明确。

阶段 1：机械、电气和单关节样机

1. 完成机身、腿部、关节、传动、限位、外壳、散热及线束设计和加工图。
2. 完成电池、BMS、配电、DC-DC、保险、急停、驱动器和接地设计。
3. 先制作单关节台架，验证扭矩、速度、回差、温升、编码器零位和过载保护。
4. 再装配整机，进行静态承重、跌落风险和线束运动干涉检查。

阶段交付：CAD/加工与装配图、电气原理图、线束图、单关节测试和保护阈值记录。
通过条件：单关节在目标载荷下稳定闭环，温升/电流合格，急停和断电行为安全。

阶段 2：嵌入式驱动和 ROS 2 硬件层

1. 实现 MCU/实时控制器的电流、速度、位置闭环和 CAN/串口/EtherCAT 通信。
2. 接通编码器、IMU、足端力、电池和温度数据，并统一时间戳与故障码。
3. 编写厂商 SDK 适配器或 ros2_control hardware plugin。
4. 落实硬件急停、驱动失能、命令超时、关节限位、过流/过温/欠压保护。

阶段交付：固件、通信协议、SDK/ros2_control 适配器、标定工具、故障码和台架报告。
通过条件：12 关节可独立低增益测试，所有传感反馈连续，拔线或故障不会保持危险输出。

阶段 3：模型、状态估计和基础运动

1. 实测尺寸、质量、质心、惯量、关节方向和零位，更新 URDF 与动力学参数。
2. 完成正逆运动学、雅可比、重力补偿和状态估计。
3. 按架空、保护绳、低增益顺序验证站起、趴下、姿态稳定和单腿轨迹。
4. 实现站立、踏步、行走、转向、步态切换和跌倒恢复，再逐步提高速度。

阶段交付：实测 URDF/动力学参数、状态估计、基础步态、参数集和安全测试报告。
通过条件：保护条件下可重复站立和低速行走，估计连续，超姿态或通信中断能安全停止。

阶段 4：全身控制和真实越障

1. 实现落脚点规划、摆动腿轨迹、MPC/WBC 或等价全身控制与接触力分配。
2. 将 STEP、CLIMB、LOW_PROFILE 升级为可反馈、可取消的 ROS 2 Action。
3. 利用足端接触和机身姿态闭环执行动作，并定义高度、坡度、速度安全包络。
4. 越障期间接管普通 /cmd_vel，成功、失败或超时后安全交还 Nav2。

阶段交付：落脚与全身控制器、越障 Action、动作参数库、失败恢复和障碍测试数据。
通过条件：各类障碍完成重复低速试验，动作可取消/超时，速度与动作控制没有争用。

阶段 5：传感器、感知和自主导航真机化

4. 在 RK3588 上完成 CPU、内存、温度、功耗、网络、延迟和长时间运行测试。

十一、常见问题
--------------

Nav2 一直未激活：
  检查 /scan、/odom 是否持续发布，map -> base_link 是否存在；查看
  nav2_readiness_monitor 日志中的 missing 项。

terrain_analyzer 等待 TF：
  检查点云 header.frame_id、该 frame 到 base_link 的 TF 和时间同步。

OpenCV 没有识别：
  检查活动图像话题、编码、HSV、Canny、min_area_px；开启 debug_mask。

视觉识别到了但没有 STEP/CLIMB：
  这是设计行为。危险动作必须由点云几何确认。

机器人一直 STOP：
  检查 /terrain/features、有效点数、/crossing/speed_scale 和
  /cmd_vel_smoothed 是否持续发布。

多个相机话题选错：
  使用 camera_topic 或 point_cloud_topic 显式指定；也可等待当前源超时后自动切换。

更换雷达后 SLAM 或碰撞保护没有数据：
  使用 sensor_compat.launch.py，不要逐个修改 YAML。检查 scan_topic 类型必须是 LaserScan；
  如果只有 PointCloud2，先运行 pointcloud_to_laserscan。

profile 启动后仍没有相机数据：
  profile 是常见命名而非驱动版本承诺。用 ros2 topic list -t 查实际 Image/PointCloud2，
  再通过 camera_topic、point_cloud_topic 覆盖；CompressedImage 先转换为 Image。

关闭时出现崩溃：
  使用最新代码，正常按一次 Ctrl+C 并等待清理，不要使用 kill -9。


十二、每次修改后的标准流程
--------------------------

1. 修改代码、配置和测试。

2. 同步检查四份根目录文档：

  README.md        使用、安装、目录和启动方式
  instruction.txt 模块职责、算法与调试原理
  connect.txt     Topic、Action、Service、TF、字段、QoS 和超时
  quickstart.txt  已完成工作、已知限制和后续路线

3. 编译测试：

  source /opt/ros/jazzy/setup.bash
  ./scripts/build.sh
  source install/setup.bash
  colcon test --event-handlers console_direct+
  colcon test-result --verbose

4. 检查差异：

  git status -sb
  git diff --check
  git diff --stat

5. 直接提交并推送 main：

  git switch main
  git pull --ff-only origin main
  git add 明确的文件列表
  git commit -m "简洁描述本次修改"
  git push origin main

禁止使用 git push --force 覆盖 main。推送前必须确认没有无关文件、构建测试通过，且
四份文档与代码处于同一版本。
