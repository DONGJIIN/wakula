Wakula 算法说明
================

一、范围
------
当前实现 SLAM、Nav2、OpenCV、点云地形感知、相机/点云融合、保守决策、越障入口
引导、未知地图前沿探索、TraverseObstacle Action 编排、Xbox 手柄 Twist 适配和离线评估。
没有实现硬件驱动、状态估计、运动学/动力学、站立步态、全身控制、真实越障控制器或完整
比赛逻辑。Gazebo 仅实现独立规则场地、传感器测试载体和流程适配器，不是机器狗动力学
仿真。任务节点可以完成“探索—入口—Action—继续探索”，但不会生成关节命令；仿真
Action 成功也不能声称真机已经具备越障能力。

二、各部分作用
------------
1. slam
   slam.launch.py：统一解析传感器 profile，并一键启动感知、SLAM、Nav2 和 RViz。
   slam.yaml：SLAM Toolbox 的地图分辨率、扫描匹配和回环参数。
   slam.yaml 中 scan_queue_size=5 只用于吸收短时 TF/调度抖动；它不是回环扫描缓存，不能
   无限制调大，否则会让旧激光积压。
   nav2.yaml：全局/局部代价地图、规划器、控制器、平滑器与恢复行为参数。
   navigate_to_pose_wakula.xml：规划失败、控制失败时清图、等待、后退、旋转再规划；
   FollowPath 显式选择 goal_checker 和 progress_checker，避免依赖空 ID 的运行期回退。
   nav2_readiness_monitor.py：复用运行期数据合同，只有 scan、odom 和 map->base_link
   均有效且源时间新鲜才激活 Nav2；缓存中“仍能查到”冻结旧 TF 不算就绪。
   navigation_health_monitor.py：检查激光 frame/样本数/角度/量程/有效率、采样时间戳、
   里程计 frame/四元数/协方差/跳变、动态 TF 源时间与断流，发布诊断并参与速度门联锁；
   /diagnostics 的 tf_age_seconds 可直接定位 TF 冻结，unavailable 表示缺失或零时间。
   sensor_profiles.yaml：常见设备默认话题；显式 launch 参数优先级最高。
   slam.launch.py：只启动核心 SLAM/Nav2/OpenCV/点云/RViz，不创建 autonomous_mission。
   autonomous_navigation.launch.py：完全独立的可选任务入口，不 include 核心 launch；启动
   即探索；Ctrl-C 先发布 /navigation/autonomy_stop=true 令 Nav2 Twist 归零，再请求取消所有
   Action 并退出，核心地图和感知继续运行。该信号不能停止失联外部控制器中的关节动作；
   必须收到取消/结果或使用硬件急停、停服确认所有权释放后，键盘/手柄才可人工接管。
   下一次启动会发布 false 解锁自动导航速度，但不会替外部控制器清除旧目标。
   它只运行标准 TraverseObstacle Action 客户端，不检测或启动 Gazebo 后端。完整仿真用
   quadruped_gazebo 的 robocon_field_teleport.launch.py 显式提供替身；真机必须接入真实控制器。
   当 Nav2 在已确认障碍的膨胀边界中止入口跟踪时，任务层不会无限重试：只有最新点云仍
   指向同一 map 位置、置信度/距离/横偏全部满足守卫，才允许交给 Action。控制器返回成功
   后先进入 VERIFYING_TRAVERSAL_RESULT：任务层用独立 TF 检查机体至少前进 0.45 m、越过
   在线感知的入口平面 0.12 m，并在 0.75 s 内无明显平移/旋转，才记录“类别 + map 位置”并
   继续选择下一前沿。验证超时或位移不足时该障碍仍留在待完成清单，稍后重新寻找和对正。
   多帧确认的比赛语义会进入任务账本。尚未成功越过时，任务优先回到当时真实可达的安全
   观察位并面向障碍重新采集；不会把 Nav2 目标放进实体中心，也不会凭历史类别直接触发
   越障。已完成与待完成清单分别发布到 /autonomy/completed_obstacles 和
   /autonomy/pending_obstacles，JSON 同时包含稳定 ID 和中文名。第三条自主任务命令所在
   终端每 5 秒打印一次“已越过/未越过”中文清单，清单改变时立即打印，便于比赛现场
   不打开第二个 topic echo 窗口也能检查进度。
   障碍专名经多帧确认后，autonomous_mission 先发送“同位置、只改变 yaw”的 Nav2 目标，
   按坡面轴或障碍前缘法向主动对正，再提交入口平移目标。单次修正最多 30°，转完等待
   新点云；最终 Action 交接要求航向误差约 7° 内。验证歧义障碍的旋转目标执行期间不会
   被下一帧 READY 提前取消，剩余 0.15 m 以上的入口平移也不会落入无命令死区。
   正常完整联调固定为三个独立进程：robocon_field_teleport.launch.py（Gazebo 数据源和
   一次性传送 Action）、slam_sim.launch.py
   （核心算法）、autonomous_navigation.launch.py（自主任务）。只启动前两项不会自主运动；
   真机只需用真实传感器/底盘替换第一项，核心算法和任务入口不变。
   任一 Nav2 目标连续 5 秒既没有 0.04 m 平移、也没有 0.06 rad 旋转进展，就取消当前
   Action 并改选目标。普通前沿/覆盖点会加入临时黑名单；若是已确认障碍入口，任务节点
   会冻结“创建接近目标时”的障碍 ID，避免近场 BAR/WALL/STEP 抖动丢失任务身份。只有
   最新观测仍属于同一 map 入口、粗类型兼容、距离不大于 2.35 m、横偏和航向均在门限内，
   才转交 TraverseObstacle，让真机控制器完成最后一段低速接近和越障；任一守卫不满足，
   就同时冷却语义记录和空间入口。此时以及“新鲜地形引导确认前沿被障碍阻挡”的情况，
   任务会交替转向 90°；转向成功后再通过普通 Nav2 安全链尝试移动 0.80 m，换一个真实
   观察站后才继续识别。该 0.80 m 平移没有速度旁路，障碍仍在正前方时会保持停车并再次
   恢复。即使当前只有通用 STEP/WALL、没有唯一
   障碍名，也会先尝试把当前粗类型和 map 位置匹配到此前多帧确认的待办记录；只有类型兼容
   且位置误差不超过 0.90 m 才复用 ID。每次回访按 8/16/32/64 秒退避，到达观察位但没有
   重新识别也不会清零，因而一个旧入口不会反复抢占整场任务。入口已到达但越障 Action 服务端
   未就绪时最多等待 5 秒，之后同样保留待办并继续探索，不能永久卡在障碍前。
   八项全部完成或到达返程时间后用 Nav2 去终点；若没有前沿、覆盖目标或可执行待办，则每次
   原地转 90° 补扫，最多 8 次（两圈）后携带当前清单返回终点。默认终点是自主任务启动时
   捕获的实时起点。默认总预算 300 秒，前 240 秒可探索/越障、最后 60 秒保留返程；正在执行
   的 Action 不会被时钟硬切断，返程失败也会继续安全恢复。终端和 /autonomy/progress 同时
   输出 elapsed_seconds 与 budget_remaining_seconds，调比赛节奏时先看实际各阶段耗时。
   正式终点不同可由外部赛务模块发布 map 坐标 /autonomy/finish_pose，核心算法不读取 world。
   Nav2 和 TraverseObstacle 的 goal response、cancel 与最终 result 各有有界通信看门狗，
   迟到回调按 generation 丢弃，迟到但已 accepted 的旧目标还会被尽力取消。server 尚未
   ready 时不会提前消耗补扫次数、恢复动作或回访退避。若响应/取消超时，任务无法证明
   远端是否仍拥有运动权，会进入 ACTION_COMMUNICATION_FAULT 并持续发布
   /navigation/autonomy_stop=true；这只锁 Nav2 Twist，不是硬件急停，也不是普通规划失败。
   禁止自动重试或人工接管：先用硬件急停/停服处理未知关节运动；Nav2 故障可重启 Nav2/
   核心栈，Traverse 故障必须停/重启外部越障控制器，归属不明时两者都处理。确认旧目标
   消失后再重启自主任务；只重启 autonomous_navigation.launch.py 或只重启核心栈不足。

   2026-08-31 三分钟流程验收：全局与局部 Nav2 代价地图都订阅地面过滤后的
   /perception/obstacle_points；任务在唯一语义、实时几何、横偏和航向满足条件后交给
   TraverseObstacle。隔离 ROS 域联合运行三个独立 launch，48 秒完成八项、pending=0，物理
   模型回到起点并进入 COMPLETED。每项都经过 Action 成功、有效位移、入口平面（直角绕杆
   使用专用位移判据）和稳定落地后验，仿真节点不能直接改任务账本。
   为可重复验收任务顺序，闪现入口使用 Gazebo 专属确定性融合样本；所以该结果只说明流程
   和三分钟预算通过，不说明 OpenCV/原始点云分类、SLAM 回环或真机运动通过。准确率测试改用
   纯 robocon_field.launch.py；不要用确定性样本调整生产识别阈值。

2. quadruped_perception
   vision_obstacle_detector.py：OpenCV 轻量识别。先缩放和 CLAHE，再做 HSV 颜色分割、
   自适应 Canny、形态学、ROI 过滤和轮廓几何。HSV 支持 Hue 0/179 环绕范围；曝光质量必须在原图上计算；原图/CLAHE
   双 HSV 掩膜补偿阴影，高光掩膜抑制灯光和金属反射边缘；随后通过同类投票率、相邻命中
   的单帧位置/尺度变化和目标框 IoU 去除瞬时误检。整个窗口可以平滑放大或横移，因此正常
   接近和转向不会被累计极差误杀；稳定输出使用当前匹配框，与最新 Image Header 同帧。
   同一相机来源还要求 Header 时间戳严格递增；DDS
   重发和驱动缓冲的乱序帧不会替换新画面、刷新心跳或重复贡献投票。相机断流、来源切换
   或 ROS 时钟回拨会清空历史，恢复后必须重新积累确认帧，不能复用旧画面的票数。
   连续蓝色横杆必须满足长宽比及最大画面占比；规则中的蓝白交替横杆会把至少三段
   高度中心对齐、尺寸相近、间距规律、跨度有限且覆盖率足够的蓝色短段合并，接近后位于
   画面下部也不会漏掉；同排但间距杂乱的蓝色物体会被拒绝。
   双立柱要求成对几何一致；另一根出画时只接受前向通道中的单根着色细柱。未着色的
   孤立水平边缘或大闭合框不再单独输出 BAR/WALL，墙面交给点云米制几何确认。
   它输出归一化图像框和置信度，不把像素尺寸伪装成真实米制高度；另发布带检测 ROI、
   原始候选和多帧确认框的 /vision/annotated_image。该调试输出使用 RELIABLE、小队列 QoS，
   与 RViz 默认 Image 订阅兼容；原始相机输入仍使用低延迟传感器 QoS。

   terrain_analyzer.py：把 PointCloud2 按采样时间变换到 base_link，截取前方 ROI，估计
   地面基准、俯仰/横滚坡度、粗糙度、障碍高度、距离、横向偏移、宽度、坑深和横杆净空；结果同时
   提供给规划层和 Nav2 local costmap。进入 Nav2 的不是原始 ROI：算法按每帧拟合地面
   计算相对高度，只保留凸起，避免合法坡面封路，同时保留 base_link 下方的低台阶。
   几何无效时发布空障碍云并由安全层 STOP。只缓存最新帧；高分辨率点云在 TF 前先做
   可复现的全幅等间隔有界采样，ROI 内再二次限点，避免 RK3588 积压且不偏向图像某一区域。
   同一来源只缓存 Header 时间严格递增的点云；重复/乱序包不能刷新来源心跳。数据源切换或
   ROS 时钟回拨会清除旧地面先验，避免上一段 bag/仿真会话把新平地误判成台阶。

   terrain_geometry.py：独立的 NumPy 几何算法，便于脱离 ROS 做单元测试。地面优先由
   最近约 30%、最多 0.65 m 的有效栅格锚定，再做高度统计、迭代 MAD 离群剔除和稳健
   拟合；这样宽台阶/桥面不会夺走地面层并把入口反报成坑。算法枚举同帧所有正/负高度
   连通域，按前缘选择通道内最近的有效结构；每个候选必须由该区域真正的异常原始回波
   支撑，不能把同格地面点计入障碍支撑。这样远处宽墙不会遮住近杆，少量近场飞点也不能
   抢占真实墙。高低异常格还必须达到八邻域格数门，再根据
   高度突变、占据分布、空洞和净空分类 CLEAR/STEP/PIT/
   WALL/BAR/POLE。连续坡面还要通过纵横跨度和低平面残差门，离散踏面继续保持 STEP；
   带支柱横杆用主高度带估计净空，70 mm 立柱允许少格但必须有足够原始回波及三维跨度。

   terrain_safety_assessor.py：比赛专名在发布到终端和自主任务前再做一次时序迟滞；新名称
   连续 3 帧一致才切换，清地面连续 4 帧才清除旧障碍。无效感知立即生效，不因滤波保留
   旧结论。该层只稳定名称，不修改同一帧的原始几何消息，便于 rosbag 追溯。
   栅格分位数已改为一次排序后的 NumPy 向量计算，避免逐格 Python quantile；确认坑洞后
   把真实低回波投影成局部代价地图虚拟障碍，但无回波盲区仍不判坑。
   无真机数据时阈值只能作为初值。

   perception_fusion.py：在两个有界小队列中全局寻找 Header 时间差最小的相机/点云对，
   能容忍回调乱序；零时间戳、重复旧帧或超过 sync_slop 的观测拒绝融合。输出把点数、
   粗糙度、坡度及确认位放入同一个原子消息。融合前再次校验类别、有限数值、归一化框和
   物理量范围，非法字段不会穿透接口。几何仍是主证据；视觉细分横杆/立柱还必须
   分别满足点云净空/窄宽度，冲突时不覆盖几何类别。vision_confirmed 只表示“视觉类别
   已通过点云类别与米制结构一致性检查”，不表示“相机检测到任意框”；CLEAR+视觉障碍、
   STEP+视觉墙等冲突组合保持 false，且不降低权威点云的类别或置信度。相机断流时等待 0.25 s 后发布纯
   点云结果，保持几何安全链连续，且明确 vision_confirmed=false。时间同步只能证明
   同一时刻，视觉框还必须与归一化前向通道相交，避免画面边缘物体与正前点云误关联；
   真机具备 CameraInfo/准确外参后可升级成三维投影关联而不改变消息接口。

3. quadruped_planning
   terrain_safety_assessor.py：vision=true 时优先使用同步后的 FusedObstacle，vision=false
   时使用旧数组路径；两种路径都只转换为 WALK/STEP/CLIMB/STOP 地形模式和 0～1 Nav2
   速度上限。STOP 立即生效；风险降低和 STEP/CLIMB 分类需多帧确认。它还把模式、限速、
   有效性和当前几何摘要原子发布为 NavigationSafety，避免未来团队跨话题拼接。不发布
   动作建议，NavigationSafety 也不能直接驱动关节。为便于现场调试，它同时发布中文障碍
   名称，并按固定周期在终端打印正前方类别、模式、限速、置信度、距离和高度。融合输入同样
   要求时间戳严格递增：重复/乱序消息不刷新感知心跳，也不能推进风险或名称确认；若持续
   重发同一帧，现有超时逻辑会按数据断流安全停车。ROS 时钟回拨时清空名称与风险投票。
   front_obstacle_name_zh() 将通用几何转换为比赛易读名称：点云直接对应直角绕杆区、坑区、
   限高杆和高墙；低横滚的 7～12° 坡面显示主斜坡，12～17° 显示木桥引坡；宽且直接
   看到 0.32 m 以上顶部、呈 7～18° 阶梯趋势并有离散踏面残差的 STEP，或满足严格
   16～24° 坡角/坑深/宽度联合条件的近场 PIT 轮廓时，显示 T 字形台阶。
   算法不读取 Gazebo 坐标，局部证据不足以区分木桥 A/B
   时会明确写“待结构确认”。单个无结构橙/蓝色块不再确认成含义模糊的 COLORED OBSTACLE；
   RViz 相机画面顶部直接叠加点云融合类别，且该显示信息不回灌视觉算法。

   已确认的台阶、坑洞、墙和横杆若仍在 1.20 m 交接区以外，会暂时转换为 WALK/0.25
   倍低速，让 Nav2 到达越障入口并对正；进入近距区停车。普通/矮立柱仍由 Nav2 代价
   地图低速避碰；高度≥0.45 m 且语义确认为直角绕杆赛项后，才进入 TraverseObstacle Action
   任务流程。该机制解决“远处识别后立即归零而到不了
   入口”的死锁，不再把比赛障碍统一当作应绕开的目标。
   全局代价地图使用 16 m × 8 m 滚动窗口，覆盖 14 m × 6 m 比赛场地；任务层只容忍
   0.30 m 的 SLAM 栅格边界发布滞后，定位真正离图时仍保持 WAITING_FOR_MAP。

   traversal_guidance.py：订阅 NavigationSafety，计算障碍中心横向偏移和对正角，发布
   APPROACH、ALIGN、READY 三阶段以及 base_link 中的相对入口 PoseStamped。入口始终位于
   障碍前方自由空间；节点不调用 NavigateToPose。autonomous_mission 负责把入口位姿转换为
   Nav2 goal，READY 后暂停 Nav2 并交给真实越障控制器，成功后恢复原导航目标。输入超时
   会发布 INVALID 并清除历史，防止 READY 粘住。同一障碍的距离、横向中心和对正角采用
   一阶低通；READY 要求连续 3 帧满足条件，并以 0.05 m 距离、0.035 rad 角度迟滞退出，
   防止停在交接边界时 ALIGN/READY 闪烁。没有有效越障目标时不发布 approach_pose，消费端
   仍必须用同时间戳 guidance 验证有效性，不能使用 RViz 中残留的旧箭头。

   autonomous_mission.py：订阅 /map 与 TraversalGuidance，从占据栅格中寻找“已知自由格
   紧邻未知格”的前沿，并按信息增益、距离和失败黑名单选择 Nav2 目标。闭合前沿先按机器人
   方位切分，再从每个扇区选择真实自由格，不能把整圈平均到已经探索过的地图中心。
   识别到越障目标后连续多帧确认并冻结其 map 坐标；在宽视场同时出现多个障碍时只接受
   同一邻域更新，避免入口目标取消抖动。到达入口且最新几何仍与冻结位置一致后才调用
   /traverse_obstacle。Action 的 ROS 状态、控制器 success、跨过入口的 map 位移和落地稳定
   四项均通过后才登记完成位置、冷却并继续找下一前沿；Nav2 拒绝、超时、Action 拒绝/
   取消、后验验证失败以及运行中 STOP 都有独立处理。算法不读取 Gazebo 模型名、障碍 world
   坐标或固定航点，因此更换正式场地布局不改源码。感知层以 CLEAR+traversal_required
   表示可量测坡面，任务层在 Action 边界显式映射成 SLOPE=7，避免运动控制器误判为平地。
   Action 前的最终闸门必须读取新鲜且 perception_valid=true 的 NavigationSafety；缺失、
   超龄或无效帧全部 fail-closed，不能用历史专名代替实时米制几何。T 字台阶允许完整顶部、
   局部踏面、7～18° 且具有离散残差的多级 STEP 趋势，以及名称层同样严格的 16～24°
   近场 PIT 踏面轮廓，但继续受高度、横滚、宽度和粗糙度上限约束，以排除主斜坡侧面。
   新鲜窗口只在 autonomous_mission.yaml 的 safety_geometry_stale_seconds 配置；真机若
   “名称正确但不交接”，先检查该消息时间戳/频率和上述米制字段，低频设备再小步增大窗口，
   不要通过放行空数据来绕过闸门。Guidance、TF、里程计和 Nav2 目标中的任一 NaN/Inf、
   非法四元数或越界枚举都会在任务边界原子拒绝。Action result Future 异常意味着旧控制权
   无法确认释放，会进入上述 ACTION_COMMUNICATION_FAULT，而不是清句柄后盲目重试。

   Nav2 仍采用标准双层规划：planner_server 的 NavFnPlanner 使用 SLAM 地图生成全局路径；
   controller_server 的 DWBLocalPlanner 使用实时局部代价地图跟踪路径和绕开临时障碍。
   /scan 同时进入全局/局部代价地图，去地面后的点云只补充 local_costmap。
   当前不切换到 D* Lite：Nav2 Jazzy 官方未提供该插件，比赛场尺度下也没有测得 NavFn
   成为瓶颈。地图变化由周期重规划、代价地图和 DWB 处理；后续真机若需要更强的足式运动
   可行性，先基准测试官方 SmacPlanner2D 或 SmacPlannerLattice，再依据规划耗时、路径质量
   和失败率决定，不能仅因算法名称较新就替换稳定基线。
   状态超时用于容纳全栈同机运行时实测约 2.7 秒的极端帧抖动；速度门仍以 0.7 秒独立
   检查评估心跳，因此不会延后控制链停车，真正断流后决策状态也会 fail-closed STOP。

   cmd_vel_gate.py（可执行名 navigation_speed_gate）：同时要求 Nav2 命令、地形评估和
   /navigation/healthy 心跳新鲜，按速度上限缩放；任一路断流、异常或上限为零就输出零
   Twist。最后读取 /scan，仅对当前运动方向检查 0.22 m 极近距离急停区，并直接发布
   标准 /cmd_vel。它不改变规划目标、不把越障改成绕行，也不替代未来驱动器急停和
   硬件看门狗。输入 Twist 的 linear.x/y/z 与 angular.x/y/z 作为一个原子命令检查；即使
   NaN/Inf 出现在当前未使用的轴，也整条归零，防止异常值穿透到未来全向底盘或驱动适配器。
   此直接速度门替代了会在当前 Jazzy 版本运行/退出时 SIGSEGV 的
   Collision Monitor 进程。

4. quadruped_teleop
   xbox_teleop.py：订阅标准 /joy，左摇杆控制前后/横移、右摇杆控制偏航；LB 只有在摇杆
   回中时按下才能解锁，之后须持续按住，松开立即归零。带量按 LB 会拒绝解锁，必须松开
   后重试。横移默认限制为当前平移档位的 60%，三个轴方向可在 YAML 独立翻转。
   A/X/Y 切换三档速度，B 锁存软件急停，Start 仅在 LB 松开且摇杆回中时清除急停。
   十字键上按下边沿使用独立进程组启动 ros2 launch slam
   autonomous_navigation.launch.py；十字键下向该组发送 SIGINT，等价于在自主任务终端
   Ctrl-C。按住不重复触发，正常退出超时才升级 TERM/KILL。管理器只记录自己创建的 PID，
   不关闭 Gazebo、slam.launch.py 或其他终端手动启动的自主任务。
   默认发布 /cmd_vel_joy，不加入 slam.launch.py；真机阶段必须经 twist_mux 与 Nav2 仲裁，
   再进入硬件安全层与驱动。手柄断流超过 0.5 s 会持续发布零速度；恢复连接后必须先
   松开再重新按下 LB，不能沿用断流前的使能状态。
   xbox_teleop.launch.py：独立同时启动 joy_node 和 xbox_teleop；不包含 SLAM/Nav2，方便
   单独调试手柄，也满足主导航 launch 不自动启动手柄的边界。自主任务仍默认关闭，只有
   十字键事件才在运行时创建独立子进程，因此 Xbox、Gazebo、SLAM 三个入口保持分离。

5. quadruped_tools
   perception_bag_evaluator.py：读取 rosbag 与标签文件，按时间匹配预测和真值，输出每类
   precision、recall、F1 和混淆矩阵，并有限搜索视觉置信度及三个高度等级。它不自动计算
   米制几何误差，也不搜索 HSV、横杆间距或全部点云阈值；这些按第五节回放逐组标定。
   stack_regression.py：仿真专用长测工具；只有显式 --allow-motion 才向 /cmd_vel_teleop
   发布速度。它交替执行矩形异路闭合与双向整圈旋转/前进/倒退，并验证多目标、1 m 绕杆
   窄通道和不可达目标恢复；持续记录 map/scan/odom/正前方名称/越障引导间隔、map/odom
   起终一致性、两路感知 Header 年龄、READY 安全合同、ALIGN/READY 边界抖动以及核心进程
   CPU/RSS。轨迹闭合只做一致性回归，不能证明 SLAM Toolbox 回环图优化。
   输出 JSON 只代表 Gazebo 软件回归，不能作为真机安全认证。

6. quadruped_description
   quadruped.urdf.xacro 只是 RViz 外形与 lidar_link、camera_link、camera_optical_frame、
   imu_link 的 TF 占位。真实安装完成后必须替换尺寸和固定变换。

7. quadruped_gazebo（独立仿真工具，不属于核心算法）
   robocon_obstacle_field.sdf：按规则 V1.0 复现 14m×6m 场地和八类障碍已公布的尺寸、
   高度、间距与颜色；world 开头的 REFERENCE LAYOUT 集中定义全部参考 pose。规则尚未
   公布障碍正式坐标，所以当前布局只用于联调，正式坐标到手后只改八个 layout_* frame。
   generic_quadruped/model.sdf：提供通用四足外观和 /scan、/odom、/imu/data、RGB、深度点云；
   固定腿仅用于辨认外形，机身由平面速度插件保持水平且没有动力学碰撞。它专门隔离验证
   SLAM/Nav2/OpenCV，不能评价步态、接触或真实越障；直接 /cmd_vel 测试可能穿过障碍。
   顶置 360° 二维雷达用可见掩码忽略测试狗自身外观，避免自遮挡和机身倾斜形成假墙。
   RGB-D 光心位于机头外侧并向下俯约 14°，外观后移到光心后方；不使用会让部分 Gazebo
   渲染后端输出全 Inf 深度的相机可见掩码。它使用 424×240@15 Hz 的仿真轻量档并关闭
   Gazebo 传感器可视化，降低同机运行
   Gazebo、SLAM、Nav2 和 OpenCV 时的渲染/桥接压力；world 物理更新率为 100 Hz，足以
   支撑测试 IMU。/clock 独立桥接，/scan、/odom、/tf、/cmd_vel 使用轻量导航桥，IMU 与
   CameraInfo 使用辅助桥；不再桥接算法未使用的 /scan/points，避免高带宽数据拖住导航。
   地图每 0.25 s（4 Hz）发布；扫描匹配最多约 10 Hz，倒退/转向达到 8 cm / 0.08 rad
   即可加入关键帧。RViz 视图跟随 base_link，但 Fixed Frame 仍保持 map。
   点云在线以 5 Hz 处理最新帧并前视 2.5 m。这些优化不改变任何标准真机接口。
   robocon_field.launch.py：只启动 Gazebo、可选测试载体、ROS 桥、仿真固定 TF 和可选的
   仿真键盘输入，不 include slam.launch.py、Nav2、OpenCV 或 Xbox。GUI 默认自动打开
   `Wakula Simulation Keyboard` 窗口，因此三命令联调无需额外键盘命令；联合测试仍必须
   在另一个终端显式启动算法。
   2D SLAM 的必要链路是 /scan、/odom、odom->base_link 和 base_link->lidar_link；RGB-D
   用于 OpenCV/点云感知，IMU 是为 RViz、时间同步和未来状态估计预留，不会被 SLAM
   Toolbox 自动融合。相机消息使用 camera_optical_frame，避免把光学点云误当成机身坐标。
   RViz 默认隐藏 TF、网格和实时 LaserScan：白色为已观测自由区、黑色为占用区、灰色为
   未知区；开放场地的白色射线边缘只是探索范围，黑色放射线才需要检查雷达水平度/TF。
   应低速覆盖通道并完成回环后，用墙线重合程度判断建图质量。
   换正式 SDF 时使用 robot_sdf、robot_name 和 publish_test_sensor_tf:=false 三个 launch 参数；
   算法入口、标准话题和节点不需要修改。
   同一 ROS_DOMAIN_ID 内只能运行一个场地 launch；两个 /clock 会触发 TF 时间回跳并使
   SLAM 丢弃扫描。算法联合命令为：
     ros2 launch slam slam_sim.launch.py
   slam_sim.launch.py 仅包装核心算法，固定 use_sim_time=true、robot_model=false，并不
   include Gazebo；因此场地和算法仍可独立启停，真机入口不受影响。
   普通 slam.launch.py 的 use_sim_time 和 robot_model 默认为 auto：入口不使用 ros2 daemon
   缓存，并多次查询当前 ROS 域的 /clock，避免 DDS 首次发现漏报后把 Gazebo 误判成真机。
   普通 slam.launch.py 自动模式的仿真摘要必须是
   simulation_detected=true/use_sim_time=true/robot_model=false；否则使用 slam_sim.launch.py
   显式锁定仿真时钟。显式入口会先打印 Wakula simulation mode；其核心摘要可能显示
   simulation_detected=false（因为无需再探测），但 use_sim_time=true/robot_model=false
   必须成立，不能在系统时间下消费 Gazebo 传感器时间戳。
   Gazebo 服务端被 Ctrl-C 或关闭窗口后，RViz 可能继续显示最后一张地图；此时 /scan、
   /odom、点云已停止，“感知数据无效”是正确的安全降级。先用 ros2 topic hz 分别检查三路。
   仿真键盘不要直接占用 /cmd_vel。Gazebo GUI 默认打开的键盘窗口把 i/j/k/l 发布到
   /cmd_vel_teleop；scripts/keyboard_teleop.sh 只作为关闭自动窗口后的排障入口。
   sim_cmd_vel_mux 令新鲜手动命令优先于算法 /cmd_vel，并将唯一结果写入
   /cmd_vel_gazebo。手动与算法都超时后输出零速度，避免遗留运动指令。
   Ubuntu 可能延迟弹出旧的 RViz 崩溃报告；以报告 Date 和最新 launch.log 为准。最新日志若为
   “rviz2 process has finished cleanly”，则该弹窗不代表当前 SLAM/Nav2/OpenCV 已崩溃。
   TF 诊断统一使用 scripts/diagnose.sh。tf2_echo 是持续输出程序，不要直接接 head 等会
   提前关闭读取管道的命令；否则 ros2run 可能产生与算法无关的 BrokenPipeError 弹窗。
   robocon_field.launch.py：只启动独立场地、测试载体和传感器/标准接口，不启动算法或 Action。
   robocon_field_teleport.launch.py：在纯场地上增加 Gazebo 专属 `/traverse_obstacle` 替身；任务
   对准后只调用一次 SetEntityPose 传送到出口并返回成功，不模拟中间轨迹、碰撞、落脚或接触。
   该入口还提供独立的三分钟上层流程回归：核心清单每新增一项后，仿真节点才把模型放到下一
   个 `layout_*` 参考观察位，并从融合层标准接口发布确定性测试样本。八项结束后模型回到 world
   起点，并用 `/autonomy/finish_pose` 同步传送后的 map 坐标。仿真节点从不发布完成清单，成功
   仍由 Action 终态、真实位移、越过入口和平稳窗口共同确认。
   该限时模式默认关闭原始深度点云桥以避免与确定性融合样本竞争，但保留 RGB、2D 雷达、里程计
   和 TF。它只验收任务编排，不能用于评价 OpenCV/点云精度或 SLAM 回环；准确率测试必须改用
   robocon_field.launch.py + slam_sim.launch.py，后者保留真实点云输入。
   sim_traversal_controller.launch.py：只在场地已经运行时单独排查该 Action。三个入口均不进入
   核心算法；autonomous_navigation.launch.py 永远只运行 Action 客户端。

三、决策原则
----------
1. 点云几何决定是否可通行；OpenCV 只辅助提醒和减速。
2. 点云不足、NaN/Inf、TF 失败或消息超时都不得当作安全地面。
3. WALK：允许 Nav2 速度；视觉可把速度降到 vision_speed_scale。
4. STEP/PIT/WALL/BAR 与坡面：远处由 Nav2 接近入口并对正，进入交接区后由任务节点调用
   TraverseObstacle；服务端不存在、拒绝或超时时保持安全状态，不得假定跨越成功。
5. POLE：普通/矮立柱由 Nav2 结合代价地图低速绕行；高度≥0.45 m 且语义确认为
   right_angle_poles 的规则绕杆赛项才触发 TraverseObstacle Action 交接。
6. 危险升级快，解除危险慢，避免阈值附近抖动。

四、推荐调参顺序
--------------
七个核心 YAML 的第一屏已经列出针对真机的“现象 -> 参数 -> 调整方向 -> 风险”，它们是
参数唯一来源：slam.yaml 管建图，nav2.yaml 管外形/规划/控制，sensor_profiles.yaml 管
话题映射，vision.yaml 管 OpenCV，terrain.yaml 管点云，terrain_navigation.yaml 管安全
限速/入口，autonomous_mission.yaml 管探索与 5 秒恢复。不要在 Python、launch 或另一份
临时 YAML 建立第二套调参入口。Python 参数声明只保留启动所需、经测试与 YAML 同步的
回退值；文档数字是带版本快照，不是部署覆盖。另一台电脑使用 Codex 时，应先读取根目录
AGENTS.md。

1. 先确认相机内参、点云单位、时间戳和 TF 方向正确。
2. 在静态平地调 ground_height_bin、grid_cell_size、ROI 和 min_valid_points。
3. 用已知高度台阶调 warning_height、step_threshold、climb_threshold、stop_threshold。
4. 用斜坡和不平路面调 max_slope、max_roughness。
5. 用坑洞、墙、横杆、立柱 rosbag 调几何阈值并统计混淆矩阵。
6. 最后在不同光照下调 HSV、CLAHE、Canny、min_image_quality、面积比例、投票率和 IoU。
   必须包含黑场、白场、阴影、逆光、频闪、反光、运动模糊和局部遮挡；分别关闭
   dual_illumination_color_mask 与 suppress_specular_glare 做 A/B 对照。
   蓝白限高杆误把同排杂物当横杆时，先降低 segmented_bar_max_gap_ratio 和
   segmented_bar_max_gap_cv；强透视下真横杆漏检时再小步提高，并逐类比较 precision/recall。
7. 只有离线指标和低速实测都通过后，才逐步放宽速度。

常见调整方向速记：
- 地图转弯跟不上：先查 TF/CPU，再减小 slam.minimum_time_interval；CPU 高则反向调。
- 平地误报障碍：先修点云外参/地面拟合，再提高地面吸收带或连通区门，不能直接删点云层。
- 阴影漏识别：先固定曝光/白平衡，再调 CLAHE/HSV；反光误检则收紧高光与颜色门。
- 擦碰：增大实测 footprint/robot_radius 或 inflation；窄通道无路径时先证明真实净空，
  再小步减 inflation，不能关闭 obstacle_layer。
- 障碍前 5 秒不动：普通目标会换点；已确认入口只有在空间、类别、距离、横偏、航向
  全部通过时交给 Action，否则冷却。极低速真机才考虑增加 nav_stall_timeout，并同时检查
  位姿进展阈值，防止定位噪声冒充运动。
- Action 成功却未计完成：按机身长度和定位噪声调完成后验，先排除服务端过早 success。
- 出现 ACTION_COMMUNICATION_FAULT：自主速度锁只保证 Nav2 Twist 归零；先用硬件急停/停服
  处理未知关节运动，再停止/重启日志指明的所有者。Nav2 故障可处理核心栈，Traverse 故障
  必须处理外部越障控制器；归属不明时两者都处理，确认旧目标消失后再重启自主任务。
  只有 rosbag/网络证明正常握手确实超过默认 2 s 时，才在 autonomous_mission.yaml 小步增加
  action_response_timeout/action_cancel_timeout；放宽只延后报警，不能修复 DDS 断连。

当前无真机时的自动回归命令（仅允许在 Gazebo 使用）：

  ros2 run quadruped_tools stack_regression --allow-motion --cycles 5 \
    --pipeline-latency-budget 0.35 --report reports/stack_regression.json

该工具默认使用 Gazebo /clock，系统时间数据源加 --no-use-sim-time。奇数/偶数轮交替执行
矩形异路闭合和双向旋转/前进/倒退；报告要求每个请求周期都有有限 map 起终指标，并同时
列出 odom 对照、核心进程 CPU/RSS 和 terrain/fused Header age p50/p95/max。该结果只叫
closed_path_pose_consistency，不证明 SLAM Toolbox 回环图优化。要验证真正回环，必须对同一
带可控 odom 比例/偏航漂移的 rosbag 做 do_loop_closing=false/true A/B，并比较 map->odom
修正和墙体重合/占用 IoU；关闭回环的对照应失败，开启后才应把误差压回阈值。

2026-08-13 基线：5 轮约 3 分 20 秒，最大闭环位置误差 0.0103 m、偏航误差
0.0152 rad，scan/odom/导航健康未持续断流；多目标和 1 m 绕杆窄通道成功，高墙内部
目标按预期失败。不同电脑应保留自己的 JSON 报告做版本对照。
新增入口稳定性基线：联合测试收到 665 帧 guidance、最大间隔 0.753 s、错误 READY 为 0；
边界复测进入 READY 6 帧且没有小于 0.35 s 的 ALIGN/READY 快速往返。

2026-08-31 无闪现逐障碍基线：Gazebo、slam_sim 和 autonomous_navigation 仍按三个独立
进程启动，测试全程未启动 robocon_field_teleport.launch.py、sim_traverse_obstacle，也未
调用 Gazebo 位姿服务。固定可观测视角下八类障碍各 40 帧，共 320/320 名称正确、320/320
几何确认、320/320 导航健康；动态入口回归 8/8 能接近/对正并进入 Action 等待。高墙会天然
遮挡墙后激光，使墙中心长期贴住 OccupancyGrid 边缘；任务层仅在“比赛语义=high_wall、
实时粗类型=WALL、非场地边界、置信度和连续帧均通过”时允许继续入口流程，其他未知边界
仍被拒绝。没有真实 /traverse_obstacle 服务时不得把入口成功记成越障成功，本轮物理跨越
为 0/8。砂砾坑识别视角必须看到真实低回波；只看到入口护边时保守保持通用 STEP，并由
换视角/回访流程重新观察，禁止为追求静态准确率把无回波区直接当坑。

代码阅读约定：terrain_safety_assessor.py 的比赛专名入口先生成不可变
ObstacleMeasurements；`height_m/pit_depth_m/roughness_m/width_m/clearance_m` 均为米，
`pitch_deg/roll_deg` 均为度。分支顺序属于安全合同，前面的规则必须比后面的通用回退使用
更多独立特征；修改顺序或阈值时必须补充对应正样本、相邻类别负样本和 NaN/Inf 失效测试。
不要在条件中重新混用 ROS 消息弧度或无单位数字。关键几何字段任一非有限时，名称层立即
失效且视觉不得覆盖；现场出现该日志应先查点云驱动、TF 和时间同步，不应放宽分类阈值。

五、rosbag 标注与评估
-------------------
本节是更换真机相机、雷达、镜头、安装位姿或比赛光照后的标准标定流程。先校准硬件和
坐标，再调整识别参数；阈值无法补偿错误时间戳、错误 TF、自动曝光漂移或深度单位错误。

5.1 标定前必须完成的检查

1. 相机固定曝光、增益和白平衡；确认 Image 与 CameraInfo 分辨率一致，Header 非零且递增。
2. 点云确认 x/y/z 单位为 m，静态平地在 base_link 中方向正确；用
   `ros2 run tf2_ros tf2_echo base_link <点云frame>` 检查外参。
3. 相机和点云必须使用同一时钟。查看 `/perception/fused_obstacle.time_skew`；若偏差随时间
   单向增长，先修驱动/PTP/NTP，不能靠增大 `sync_slop` 掩盖。
4. 用卷尺、直尺和角度仪记录标定物真值：台阶高度、坑深、坡角、横杆下沿净空、立柱宽度、
   相机到障碍距离和观察角。真值与 bag 名称写入同一张测试记录表。

5.2 采集矩阵

每一类障碍和 CLEAR 空场都至少覆盖：正对、左右约 15°/30°；近、中、远；静止和低速运动；
正常光、阴影、逆光、过曝。视觉负样本必须包含地平线、队服、蓝色散物、灯具、反光金属、
局部遮挡和运动模糊；点云负样本必须包含黑色表面、反光面、无回波区、孤立/相邻飞点和坡面。
工具的硬下限是每条链路 20 个已匹配标签，但这只够检查流程；建议每个关键类别至少 50 个
有效样本，并另录一份不同路线/光照的验证 bag，不能从同一次静止画面复制样本凑数。

标准话题使用：

  ./scripts/record_bag.sh
  # 指定外置硬盘目录时：
  ./scripts/record_bag.sh /media/<用户>/<磁盘>/wakula_bags
  ros2 bag info bags/<bag名>

若驱动没有 remap 到默认话题，先在 sensor_profiles.yaml 对齐；临时采集则按
scripts/record_bag.sh 中的话题清单替换成实际 Image、CameraInfo 和 PointCloud2 名称。

5.3 生成并填写标签

  mkdir -p reports
  ros2 run quadruped_tools perception_bag_evaluator bags/<bag名> \
    --write-label-template labels.csv --sample-period 0.5

CSV 列固定为 `timestamp_ns,elapsed_s,vision_label,terrain_label,notes`。不要修改 timestamp_ns：

- vision_label：`none`、`poles`、`height_bar`、`wall`、`colored_obstacle`。标签表示该时刻
  相机前向有效区内的人工真值；不想评价视觉的行留空，不能用 `none` 代替“不确定”。
- terrain_label：`WALK`、`STEP`、`CLIMB`、`STOP`。WALK 表示几何可由 Nav2 通行/绕杆，
  STEP 和 CLIMB 表示按团队冻结的高度能力分级，坑、墙、限高杆等必须交接或禁止通行的
  危险结构标 STOP；不想评价点云风险分级的行留空。
- notes：记录实际障碍名、卷尺高度/坑深/净空、角度、距离、光照和异常。当前评估器不解析
  notes 中的米制真值，它用于人工对照 TerrainFeatures，不能谎称工具已自动计算几何误差。

标签必须根据原始图像、点云和现场记录填写，不能照着算法终端输出抄答案。模糊到人工也
无法判断的帧应留空，并在 notes 写明原因。

5.4 生成报告和有限参数建议

  ros2 run quadruped_tools perception_bag_evaluator bags/<bag名> \
    --labels labels.csv \
    --report reports/perception_report.json \
    --suggestions reports/calibration_suggestions.yaml \
    --validation-fraction 0.30 --minimum-samples 20

报告包含混淆矩阵、accuracy/Wilson 95% 区间、macro-F1 和逐类 precision/recall/F1。优先看
危险类别 recall（漏检）和 CLEAR/none 的 false positive（误停），不能只看总体 accuracy。
建议文件只会搜索 `vision_min_confidence` 与 `step_threshold/climb_threshold/stop_threshold`；
它不会自动优化 HSV、ROI、蓝段间距、地面分割、坑/墙/杆阈值，也不会自动写入正式 YAML。
先看 validation 指标，再手工把通过的单个建议复制到参数归属文件并注明 bag/commit。

5.5 三类参数分别怎么调

A. 相机颜色和图像质量（vision.yaml）

1. 从正常光与最暗仍可用帧抽取 HSV；先确定 H，再收紧 S/V 排除灰白地面和灯光。
2. 在 `/vision/debug_mask` 检查颜色像素，在 `/vision/annotated_image` 检查最终框。颜色掩膜
   正确但没有框，才调整面积/结构；原图已拖影，先缩短曝光而不是降低质量门。
3. 依次调整 HSV、CLAHE/高光、面积、质量、多帧确认；每次只动一组并重新跑报告。

B. 蓝白横杆间距（vision.yaml）

1. 收集真横杆在近/中/远和 ±30° 下的蓝段，同时加入同排蓝色杂物、队服和广告牌负样本。
2. `segmented_bar_max_gap_ratio` 是“最大白色间隙 / 蓝段中位宽”；
   `segmented_bar_max_gap_cv` 是各间隙离散系数。误报时小步降低，强透视真杆漏检时小步提高。
3. 必须同时保留最少三段、尺寸相似、水平对齐、长宽比和画面占比门；不得为召回率删除守卫。
4. 每组值在独立验证 bag 上统计 height_bar 的 precision/recall，并检查 poles 不被混淆。

C. 点云几何（terrain.yaml 与 terrain_navigation.yaml）

1. 空场先调 ROI、`ground_height_bin` 和 `grid_cell_size`，要求地面高度/坡度稳定且不报障碍。
2. 用 5/7/10 cm 标定块调低台阶；用已知坑深调 `pit_depth_threshold`；用墙高、横杆净空和
   立柱宽度分别调对应阈值。每类都要检查 `valid_points` 和连通区，不能让单个飞点通过。
3. 对同一真值至少取多个角度/距离，比较 TerrainFeatures 的 `obstacle_height`、`pit_depth`、
   `slope_pitch/roll`、`clearance_height`、`width`。先消除系统偏差，再收紧类别阈值。
4. 几何稳定后才把风险分界写入 terrain_navigation.yaml；STEP/CLIMB/STOP 是导航标签，
   不是四足真实能力。真机可跨越上限必须由运动团队逐障碍安全测试确认。
5. 最后依次降低 `transform_max_points`、`max_points`、`processing_hz` 测 RK3588；任何降采样
   都要重新比较危险类别 recall 和米制误差，不能只看 CPU 下降。

5.6 修改 HSV/间距/点云算法后的离线重算

评估器能在原有低带宽结果上搜索置信度/高度阈值，但 HSV、横杆间距或点云几何改变后必须
用原始话题重新运行节点。三个终端按下面方式操作，播放时不要把 bag 内旧算法输出一起发布：

  # 终端 1a：启动视觉节点（只测点云时省略）
  ros2 run quadruped_perception vision_obstacle_detector --ros-args \
    --params-file src/quadruped_perception/config/vision.yaml \
    -p use_sim_time:=true -p image_topic:=/实际image

  # 终端 1b：另开终端启动点云节点（只测视觉时省略）
  ros2 run quadruped_perception terrain_analyzer --ros-args \
    --params-file src/quadruped_perception/config/terrain.yaml \
    -p use_sim_time:=true -p input_topic:=/实际points

  # 终端 2：只记录本次参数重新计算的低带宽输出
  ros2 bag record --use-sim-time -o derived_<参数组> --topics \
    /vision/obstacle_evidence /terrain/features

  # 终端 3：只播放原始传感器和 TF；按实际话题替换
  ros2 bag play bags/<bag名> --clock --topics \
    /实际image /实际points /tf /tf_static

然后为 `derived_<参数组>` 重新生成标签模板/报告。若只测视觉或只测点云，录制和播放命令
删除另一条链路即可。所有节点退出后再开始下一组，防止多个发布者污染结果。

5.7 建议的首轮验收线

以下只是拿到真机后的首轮工程门槛，不是比赛官方指标：验证集每个关键类别不少于 50 个
独立样本；危险类 recall 建议不低于 0.90，STOP 类建议不低于 0.95，macro-F1 建议不低于
0.85；已知尺寸标定物的高度/坑深/净空中位绝对误差建议不超过 0.02 m。若传感器规格或
运动安全要求更严，应提高门槛。任何类别样本不足、置信区间过宽、时间对齐异常或只在训练
bag 上达标，都不能宣称标定完成。

每次参数变化必须保留：参数文件/commit、bag、标签、报告、设备和固件、安装位姿、光照、
每类样本数、逐类指标与米制误差表。不要只写“识别正常”。

六、真机接入时的最小改动
----------------------
推荐硬件基线：
- 性价比方案：RPLIDAR S2E 规格档 2D 雷达 + Orbbec Gemini 2 L 规格档 RGB-D。
  雷达至少满足 360°、暗色目标 8 m、10 Hz、角分辨率 0.5°、精度约 3 cm、稳定时间戳；
  相机至少满足主动双目、RGB/深度优先全局快门、近端 0.25 m、有效距离 3 m、水平 FOV
  80°、640×400@15 Hz、USB 3、RGB/Depth 同步和 PointCloud2。
- 强光/三维冗余方案：Livox Mid-360 规格档 + Gemini 2 L。3D 雷达至少满足近盲区 0.2 m、
  H360°、垂直 FOV 45°、10 Hz、100 kpoint/s、Ethernet/PTP 和 IP65；同时输出 PointCloud2，
  并从水平高度带生成 /scan 供现有 2D SLAM 使用。
- 官方代表规格：S2E 10 Hz/32 ksample/s/0.1125°/Ethernet/IP65；Gemini 2 L 深度
  0.2～10 m、H91°×V66°、1280×800@30 Hz、RGB/IR 全局快门、144 g；Mid-360
  H360°×V59°、0.1 m 近盲区、200 kpoint/s@10 Hz、IP67、6.5 W、265 g。
- RK3588 初始运行相机 640×400 或 640×480@15～30 Hz，在线视觉/点云算法保持 5 Hz；
  Mid-360 先限到每帧 40000 点再降采样。强日光、黑色材料、反光金属和运动振动必须录
  rosbag 实测，厂商标称参数不能代替现场验证。

1. 传感器驱动发布标准 Image、PointCloud2、LaserScan、Odometry 和 TF。
2. 在 sensor_profiles.yaml 新增 profile，或启动时传四个 topic 覆盖参数。
3. 修改 URDF 中传感器固定 TF，并用静态场景核验点云方向。
4. 用真机 rosbag 重调参数；上层算法无需绑定具体厂家 SDK。
5. 真机模型接管 TF 时设置 robot_model:=false，避免重复发布固定变换。
6. 底盘稳定输出 /odom、odom->base_link 并消费最终 /cmd_vel 后，运行
   scripts/check_integration.sh 核验实时消息、frame_id、TF、算法输出和消费者。
7. 未来运动/越障模块读取 /traversal/guidance，并用 /terrain/navigation_safety 复核
   perception_valid、时间戳和几何；两者只是入口/环境合同，动作执行、反馈、取消和硬件
   安全须由其独立实现。

七、跨团队接口设计原则
------------------
1. 核心算法只依赖标准 Image、PointCloud2、LaserScan、Odometry、TF 和 Twist，不导入厂家 SDK。
2. 厂家话题差异只放进 sensor_profiles.yaml 或 launch 参数，不复制感知节点。
3. /perception/fused_obstacle 是感知内部原子结果；/terrain/navigation_safety 是稳定环境
   摘要；/traversal/guidance 是 Nav2 入口与运动接管合同；/cmd_vel 是 Nav2 给未来底盘的
   标准速度输出。
4. 接口消息中的 NaN/Inf 在发布边界归零；任何关键证据非法、点数不足或超时均按 STOP。
5. 新硬件先录 rosbag 离线调参，再断开执行器运行全栈，最后才由硬件团队低速接入 /cmd_vel。
6. 查节点作用、归属和关键输入输出时，以 connect.txt 第二节为速查入口；消息字段、类型和
   真机要求继续查看该文件后续章节，不要只根据 ros2 topic list 猜测节点职责。
7. profile 和 launch 覆盖都只接受以 / 开头的绝对话题；不要把节点 namespace 当作硬件适配
   手段，否则同一条启动命令复制到另一台机器人后可能订阅到不同位置。
8. 新机器先执行 scripts/check_integration.sh --inputs-only，只验证驱动层；算法启动后再执行
   默认完整检查。需要把真实越障控制纳入验收时增加 --require-traverse-server。

八、推荐代码阅读顺序
----------------
1. 先看 slam/launch/slam.launch.py，理解完整栈如何组合和 remap。
2. 再看 quadruped_perception 的模块级说明和纯函数，理解 OpenCV、点云与融合算法。
3. 然后看 quadruped_planning，理解感知如何变成模式、限速和失效安全速度。
4. 最后结合 config/*.yaml 注释、行为树 XML 和 quadruped_interfaces/msg 核对参数与接口。
5. 注释解释“为什么这样做”和安全边界；实际运行合同仍以代码、消息定义和 connect.txt 为准。
6. 需要场地联调时再看 quadruped_gazebo/worlds 下的 REFERENCE LAYOUT；仿真不得反向成为算法依赖。

九、Isaac Lab 后续开发边界
----------------------
强化学习统一采用 Isaac Lab/Isaac Sim，并在独立 NVIDIA GPU 工作站训练；当前仓库不安装
训练环境，也不在缺少真机质量、惯量和执行器参数时伪造策略。后续先冻结训练与真机共用的
观测/动作字段，再按平地、坡面、单障碍、连续障碍做课程训练与域随机化。策略部署到 RK3588
前必须通过离线回放、限幅、超时停车和保护绳验证；策略负责运动控制，不替代现有
SLAM、Nav2、OpenCV、任务编排及安全链。

十、移植到已有机器人代码仓库
--------------------------
本节面向“底盘、状态估计、运动控制等其他部分已经写好，只缺本项目算法”的情况。迁移的是
ROS 2 源码包和接口合同，不是整个 ~/wakula 目录；`build/`、`install/`、`log/`、Gazebo
场地、Xbox 和离线测试工具都不是目标机器人运行依赖。

本次对接前提已经确定：目标机器人没有 SLAM、Nav2 和本项目 OpenCV/点云感知，因此采用
完整移植，不使用“只复制感知包”的精简方案。目标机器人仍负责驱动、里程计/状态估计、
本体与传感器 TF、底层运动控制、急停及真实越障 Action 服务端。

1. 先盘点目标仓库已有能力

   - 已有驱动/状态估计必须继续提供 LaserScan、Odometry、Image、PointCloud2 和 TF。
   - 目标没有 SLAM：由本项目 SLAM Toolbox 发布 `/map` 与 `map -> odom`。
   - 目标没有 Nav2：由本项目 Nav2 提供地图规划、局部规划和 `/navigate_to_pose`。
   - 已有底盘安全层或 twist_mux 时，它继续拥有最终速度和急停权限。
   - 目标仓库若已经存在同名 `quadruped_interfaces`，只能保留一个版本；修改消息包名需要同步
     修改所有 Python import、Action 客户端/服务端并全量重编，不能让两个同名接口混在 overlay。

2. 固定迁移集合

   完整算法栈复制以下六个源码目录：

     src/quadruped_interfaces
     src/quadruped_description
     src/quadruped_perception
     src/quadruped_planning
     src/quadruped_bringup
     src/slam

   六个目录必须一起维护版本；其中 `slam` 提供目标机器人缺少的 SLAM Toolbox 和 Nav2，
   perception/planning 提供 OpenCV、点云、融合、地形判断和任务层。真机运行使用
   `robot_model:=false`，由目标机器人的 URDF/robot_state_publisher 提供本体及传感器 TF。
   `quadruped_gazebo` 不是 `slam` 的硬依赖，不需要随算法迁移。

   本节后续使用的 `scripts/check_integration.sh` 和 `scripts/record_bag.sh` 位于 Wakula 根目录，
   不在六个 ROS 包内。需要这些对接/录包工具时，把两份脚本一并复制到目标工作空间的
   `scripts/`，或保留 Wakula checkout 从其中执行；它们不是机器人运行期依赖。

3. 在目标工作空间构建

     cd <目标工作空间>
     source /opt/ros/jazzy/setup.bash
     rosdep install --from-paths src --ignore-src -r -y
     colcon build --symlink-install --packages-select quadruped_interfaces
     source install/setup.bash
     colcon build --symlink-install --packages-up-to \
       quadruped_perception quadruped_planning quadruped_bringup slam
     source install/setup.bash

   不要从第二条 build 中删除 `bringup` 或 `slam`。建议记录迁移所用 Git commit；上游
   Action/msg 改动后必须让客户端、服务端和接口包使用同一版本重新构建。

4. 完整算法启动方式

   目标传感器、里程计和 TF 已经启动后，一条命令启动本项目 SLAM、Nav2、OpenCV、点云、
   融合和安全决策：

     ros2 launch slam slam.launch.py robot_model:=false \
       scan_topic:=/实际scan odom_topic:=/实际odom \
       camera_topic:=/实际image point_cloud_topic:=/实际points

   不要另外启动目标仓库中的 SLAM/Nav2，也不要只运行 `quadruped_bringup` 代替上述完整入口。
   若目标已有底盘 twist_mux/安全仲裁器，在同一命令末尾增加 `speed_gate:=false`。此时
   Wakula velocity_smoother 仍发布 `/cmd_vel_smoothed`，但不再有节点发布最终 `/cmd_vel`；
   目标仲裁器必须把它接成自动速度候选，并同时消费 `/terrain/navigation_safety`、
   `/navigation/healthy`、`/navigation/autonomy_stop`，执行命令超时、雷达/硬件急停后唯一
   发布 `/cmd_vel`。`autonomy_stop=true` 只封锁自动候选，不能封锁人工分支。这只改变最终
   速度所有权，不会关闭 SLAM/Nav2/感知。
   若采用本项目速度门，必须令 Nav2 controller 输出 `/cmd_vel_nav`、
   velocity_smoother 输出 `/cmd_vel_smoothed`，本项目 gate 独占最终 `/cmd_vel`；同时迁移
   navigation_health_monitor 或由目标仓库可靠发布 `/navigation/healthy`。不能把 Nav2 和
   gate 都接在同名 `/cmd_vel`，否则会形成多个发布者甚至反馈环。

5. 可选自主任务与越障控制

   自主任务需要 `/map`、`map -> base_link`、标准 Nav2 `/navigate_to_pose`、实时
   `/traversal/guidance` 和 `/perception/front_obstacle_name`。复制 `slam` 包时使用：

     ros2 launch slam autonomous_navigation.launch.py use_sim_time:=false

   真机运动组必须提供 `/traverse_obstacle` Action 服务端；没有服务端时任务只会等待，不会
   生成腿部动作。目标仓库仍负责 Action 控制权仲裁、接触/姿态闭环和硬件急停。

   默认 `autonomous_mission.yaml` 使用 300 秒总预算和 60 秒返程预留。真机场地、步态速度或
   规则时限变化时，应先用 rosbag/任务日志统计“自由空间导航、识别对正、单项 Action、返程”
   四类耗时，再调整 mission_timeout/return_time_reserve；后者必须小于前者。不要为抢时间
   删除语义、空间、横偏、航向或完成后验守卫。Gazebo 替身是一次位姿传送，没有可移植的
   动作时长；真机 Action 用接触、姿态和落地稳定判据决定何时结束。

   若返程日志反复出现 return_home made no pose progress，同时 terrain mode=CLIMB/STOP、
   `/cmd_vel_smoothed` 是“小线速度 + yaw”而最终 `/cmd_vel` 为零，先检查
   stopped_rotation_linear_tolerance。默认 0.12 m/s 用于接纳 DWB 约 0.10 m/s 的转向主导
   请求，速度门随后强制 linear=0、只保留有界 yaw。真机若正常转向附带值更小可下调；绝不
   通过增大该参数开放障碍前线速度，修改后必须复测 360° 雷达急停和人工停止。
   若最终 `/cmd_vel` 与 `/cmd_vel_smoothed` 都为零并且 return_home 恰好每 5 秒被取消，说明
   任务层打断了 Nav2 行为树恢复；返程专用 return_nav_stall_timeout 默认 20 秒，探索仍为
   5 秒。若 20 秒后仍是纯前进请求、正前方 traversal_required=true，任务会先取消返程，
   执行 failed_entry_turn_angle 转向和 failed_entry_escape_distance 安全换站，再重试终点；
   换站阶段继续受雷达、地形和健康门约束。真机先观察 Spin/BackUp 何时开始，再调整该值，
   不要关闭 Nav2 碰撞检查。
   若窗口已经延长但 `/cmd_vel_smoothed` 是较大线速度叠加 yaw、`/terrain/speed_limit=0`、
   最终 `/cmd_vel` 仍全零，应检查 `/navigation/rotation_recovery`。任务在返航、探索、覆盖、
   回访、接近、对正和换视角等 Nav2 拥有转向的阶段以 4 Hz 发布 true；速度门只提取最大
   0.30 rad/s yaw 并强制 linear=0，0.8 秒未收到心跳立即失效。该许可的目的只是先转开
   正前方旧障碍，限速恢复后仍由 Nav2 正常平移；HANDOFF、TRAVERSING 和 entry_escape
   不使用该许可；
   禁止在真机上把它改成线速度旁路，修改后要复测雷达急停、感知断流和 Ctrl-C 停车。

   对“几何成立但名称有歧义”的目标，两次附加视角现在按机器人 map 驻留点计数，不按会随
   相机朝向移动的桥/坡/坑最近前缘计数。若日志在同一位置仍反复从 1/2 开始，先检查
   map->base_link 是否跳变，再按真实定位噪声调整 semantic_verification_lock_radius；不要
   单纯增加最大尝试次数，否则会消耗比赛预算。两次耗尽后本轮看到的各前缘会一起短暂冷却。

   若日志每 5 秒出现 frontier/coverage made no pose progress，并且同时有
   traversal_required=true，先观察是否随后出现 changing observation station。默认转角由
   failed_entry_turn_angle=1.571 rad 控制，换站距离由 failed_entry_escape_distance=0.80 m
   控制：相机视场窄、长结构侧视仍无法分型时，可把转角逐次增加约 5°；空间狭窄或换站目标
   经常被局部代价地图拒绝时，把距离每次减小 0.10 m。不要把转角一次调到超过 90°，也不要
   为了移动而放宽线速度门。若低速真机确实在移动却被误判停滞，应先确认 `/odom` 连续、
   无跳变，再小幅下调 nav_progress_translation 或 nav_progress_rotation；阈值过小会把打滑、
   原地抖动误判成有效进展，从而失去 5 秒脱困。

6. 真机分阶段调试流程

   必须按 6.1～6.8 顺序推进。前一阶段不通过时不要带病进入下一阶段，也不要一上来启动
   autonomous_navigation。首次接电使用支撑架/保护绳、实体急停和一名独立安全员；先禁止
   电机使能。`use_sim_time:=false`，真机不得保留 Gazebo 的 `/clock`。

   6.1 确认硬件原始输入（电机禁用，算法不启动）

     cd <目标工作空间>
     source /opt/ros/jazzy/setup.bash
     source install/setup.bash
     ros2 topic list -t
     ./scripts/check_integration.sh --inputs-only \
       --scan /实际scan --odom /实际odom \
       --image /实际image --points /实际points

   再分别观察频率和单帧内容：

     ros2 topic hz /实际scan
     ros2 topic hz /实际odom
     ros2 topic hz /实际image
     ros2 topic hz /实际points
     ros2 topic echo /实际odom --once
     ros2 run tf2_ros tf2_echo odom base_link
     ros2 run tf2_ros tf2_echo base_link <雷达frame_id>
     ros2 run tf2_ros tf2_echo base_link <相机或点云frame_id>

   通过标准：检查脚本为“失败 0”；消息持续更新且时间戳来自同一时钟；`/odom` 的
   `header.frame_id=odom`、`child_frame_id=base_link`；ROS 坐标为 x 前、y 左、z 上；雷达、
   相机和点云 TF 与实测安装位置一致。静止时里程计不能持续漂移，缓慢移动/转动时符号正确。
   不满足时先修驱动、时钟同步、URDF/静态 TF 或状态估计，不要通过放宽算法阈值掩盖问题。

   6.2 被动启动感知与 SLAM（仍不允许算法驱动真机）

     ros2 launch slam slam.launch.py \
       use_sim_time:=false robot_model:=false nav2_enabled:=false speed_gate:=false \
       scan_topic:=/实际scan odom_topic:=/实际odom \
       camera_topic:=/实际image point_cloud_topic:=/实际points

   `robot_model:=false` 避免占位 URDF 与真机 TF 冲突；`nav2_enabled:=false` 和
   `speed_gate:=false` 保证本阶段没有最终 `/cmd_vel`。在 RViz 中检查 LaserScan、Map、TF、
   PointCloud2 和 `/vision/annotated_image`。另开终端观察：

     ros2 topic hz /map
     ros2 run tf2_ros tf2_echo map base_link
     ros2 topic echo /navigation/healthy
     ros2 topic echo /perception/front_obstacle_name
     ros2 topic echo /terrain/navigation_safety
     ros2 topic echo /traversal/guidance

   通过标准：`map -> odom -> base_link -> sensor` 连通；点云与地面/墙面重合；无遮挡时不应
   长期报告危险障碍；放置一个已知障碍后，名称、距离、横向偏差和阶段能稳定更新；遮住或
   断开传感器后 `perception_valid` 失效并进入 STOP，而不是保持旧的 READY。

   6.3 单独验证 SLAM

   保持 6.2 的启动方式，用目标机器人已有的人工控制以低速走“直线—原地正反转—倒退—闭合
   小环路”。不要直接搬动机器人，除非状态估计能同步反映这次位移。观察 RViz 中机器人不能
   跑出最新地图，旋转和倒退时扫描不得明显拖尾，回到起点后墙体不应出现多层重影。保存一张
   调试地图：

     mkdir -p maps
     ros2 run nav2_map_server map_saver_cli -f maps/real_site_debug

   若建图跟不上，按 `/scan` 频率与时间戳、`/odom`、激光外参、`map -> odom` 的顺序排查；
   优先修数据源，最后才调整 `src/slam/config/slam.yaml`。每次只改一组参数并记录 rosbag。

   6.4 标定和调整 OpenCV/点云识别

   完整采集矩阵、CSV 标签含义、离线重算、参数归属和首轮验收线统一按第五节执行，不在
   真机接入章节复制第二套流程。终端名称只是人工速查，程序验收应以强类型消息为准：

     ros2 topic echo /perception/fused_obstacle
     ros2 topic echo /perception/front_obstacle_name
     ros2 topic echo /terrain/navigation_safety

   先完成 CameraInfo、相机/点云共同时间源和 `sensor_frame -> base_link` 外参，再运行
   `scripts/record_bag.sh`。禁止只看一次终端输出就改阈值；HSV/横杆间距/点云几何修改后必须
   用原始话题重新计算低带宽输出，不能直接用旧 bag 内的预测冒充新参数结果。调试工具可留在
   开发机，不是目标机器人的运行依赖。

   6.5 启动 Nav2，但先不接电机

     ros2 launch slam slam.launch.py \
       use_sim_time:=false robot_model:=false speed_gate:=false \
       scan_topic:=/实际scan odom_topic:=/实际odom \
       camera_topic:=/实际image point_cloud_topic:=/实际points

   等待 `/navigation/healthy=true`，检查 Nav2 生命周期节点已经 active。在 RViz 设置一个位于
   已知自由区内的近距离目标，确认全局路径、局部代价地图和 `/cmd_vel_smoothed` 正常，但本
   阶段不把速度送给驱动。若 Nav2 不激活，优先检查 `/scan`、`/odom`、TF 和时间戳；若路径
   穿墙，检查地图/footprint/costmap；若原地震荡，检查里程计符号和局部控制器参数。

   6.6 低速接入真机运动

   首先确定最终速度只能有一个所有者：使用本项目速度门时保持 `speed_gate:=true`；目标已有
   twist_mux/硬件安全层时设为 `speed_gate:=false`；目标层必须订阅 `/cmd_vel_smoothed` 作为
   自动候选，同时订阅 NavigationSafety、navigation/healthy 和 autonomy_stop 后唯一发布
   `/cmd_vel`，否则 Nav2 速度不会送到真机。执行：

     ros2 topic info /cmd_vel --verbose
     ./scripts/check_integration.sh \
       --scan /实际scan --odom /实际odom \
       --image /实际image --points /实际points

   完整检查要求最终速度存在真实运动控制订阅者。先在平坦空场发送 0.5～1.0 m 的 Nav2 目标，
   限制线速度/角速度并始终可急停；再测倒退、连续旋转、窄通道、死路和恢复。验证取消目标或
   Ctrl-C 算法后 Nav2 自动速度归零；仅在 Nav2/TraverseObstacle 已确认释放运动所有权后，
   独立人工控制才可按目标机器人的仲裁规则接管。未确认的外部关节动作先用硬件急停处理。

   6.7 接入真实越障 Action 和自主任务

   先确认运动组服务端和类型：

     ros2 action list -t | grep traverse_obstacle
     ./scripts/check_integration.sh --require-traverse-server \
       --scan /实际scan --odom /实际odom \
       --image /实际image --points /实际points

   先单独验证一个低风险障碍：Nav2 到达入口、`guidance` 从 APPROACH/ALIGN 稳定进入 READY、
   Action 接管、真实控制器完成动作并稳定落地、任务层再次用地图位姿确认已经越过入口。
   只有以上条件全部满足才允许 Result.success=true。单障碍重复通过后才启动自主任务：

     ros2 launch slam autonomous_navigation.launch.py use_sim_time:=false

   观察 `/autonomy/state`、`/autonomy/event`、`/autonomy/completed_obstacles` 和
   `/autonomy/pending_obstacles`。不要在真机启动 Gazebo 的 `sim_traverse_obstacle` 替身。

   6.8 故障、长测与交付记录

   在支撑架/保护绳条件下依次制造相机、点云、雷达、里程计断流和 TF 缺失；确认健康状态
   变 false、安全模式进入 STOP、自动速度归零，恢复数据后不会无条件恢复旧动作。然后按
   “平地 10 分钟—单障碍重复—多目标—半场—整场”递进长测，记录 CPU、内存、温度、降频、
   话题频率、定位漂移、误识别、Nav2 恢复次数和 Action 成败原因。每次测试保存 Git commit、
   参数文件、硬件/固件版本、rosbag 和结果表，禁止只写“运行正常”。

   完整检查全部通过只代表 ROS 接口和算法数据链对齐，不代表真机步态或越障安全已经验收。

7. 参数合同与节点级回归

   感知、规划和 SLAM/Nav2 健康节点采用 fail-fast 参数合同。修改 vision.yaml、terrain.yaml、
   terrain_navigation.yaml、autonomous_mission.yaml 或 nav2.yaml 后，应先运行对应包测试再启动
   全栈。
   ROI 上下界、HSV 三元组、处理频率、点数、同步/断流窗口、STEP/CLIMB/STOP 阈值、入口距离、
   确认帧数、任务投票窗口、绝对话题和速度门输入/输出均在节点构造阶段校验；配置非法时节点
   会主动退出并一次打印同组全部错误。不要把该退出改成 warning 或静默夹紧，否则现场容易把
   配置错误误判为识别不准。`resize_width=0` 与 `transform_max_points=0` 是明确支持的“关闭上限”
   值，其余要求正值的处理周期和超时不能用 0 表示关闭。HSV 的 Hue 使用 OpenCV 0～179：
   `lower_h > upper_h` 明确表示跨越 179→0 的环绕色段；S/V 不环绕，lower 仍不得大于 upper。

   节点级测试不依赖 Gazebo：它通过真实 DDS 发布 TerrainFeatures/VisionObstacle 验证同步融合，
   只发布点云时验证超时后降级，并通过真实 20 Hz 速度门定时器验证过期非零命令会被明确的零
   Twist 覆盖。SLAM 节点测试还通过真实 LaserScan、Odometry 与动态 TF 验证健康状态由 false
   进入 true，并验证 scan/odom 继续而 TF 停更时重新变为 false。修改 QoS、话题、定时器或构造参数时必须保留这些
   回归，不能只测试纯函数。当前全工作区测试数量见 README 与 quickstart 顶部；不启动传送/闪现服务的
   Gazebo 固定视角复测取得八类 317/317 正确专名和 100% 导航健康，动态 T 台完成 READY 与
   控制器等待。该结果只验证识别、导航入口和安全交接，不代表真实腿部跨越成功。

8. 多候选传感器的有效源规则

   相机和点云节点允许配置多个常见默认话题，但“DDS 有消息”不等于“传感器有效”。候选 Image
   必须先通过 frame、非零且新鲜的 Header 时间、宽高、step、缓冲区长度和 CvBridge 编码检查；
   候选 PointCloud2 还必须具有一致的 width/height/point_step/row_step/data，以及不越界的单值
   FLOAT32/FLOAT64 x、y、z 字段。只有通过合同的消息才能刷新 active source 心跳。

   因此主话题持续发送空帧、坏编码、缺字段、截断数据或旧 rosbag 帧时，不会永久压住健康备用
   话题。现场出现 `Ignoring invalid ... contract` 时先检查驱动时间戳、frame、编码和消息布局，
   不要通过删掉校验让坏流取得所有权。正式 rosbag 回放必须使用 `--clock` 并让算法启用仿真时钟。
