Wakula 通信合同
===============

一、约定
------
ROS 2 Jazzy；长度单位 m，角度 rad，时间来自消息 Header。算法内部坐标目标为 base_link，
导航 TF 树为 map -> odom -> base_link -> sensor_frame。话题显式覆盖优先于 profile；默认
名称尽量遵循 ROS 2，以便更换设备时只 remap。
通信字段以 msg/YAML/launch 中的中文注释为代码侧依据；本文件负责跨节点速查，避免重复抄写
全部内部实现。

参数不属于通信接口，不在本文件复制默认值。真机调参按各核心 YAML 顶部索引进行；话题/
frame 差异只放 sensor_profiles.yaml、launch remap 或 TF。另一台电脑上的 Codex/代码助手应
先读取根目录 AGENTS.md，其中定义了模块边界、参数归属和接口变更时必须同步的文档/测试。

节点会在建立通信实体前校验关键参数和绝对话题。ROI、阈值、超时或同步窗口非法，或者速度门
`input_topic` 与 `output_topic` 相同时，节点会明确启动失败，以阻止隐蔽错接和 Twist 自反馈；
这属于预期安全行为，不是 DDS 断连。先按终端中 `invalid ... parameters` 的完整列表修正 YAML，
不要通过删除校验绕过。

二、节点信息
----------
本节用于快速判断“节点做什么、数据从哪来、送到哪里”。消息字段、类型和真机接入要求见
第三至第六节；完整参数以各节点配置文件为准。

2.1 感知节点

/terrain_analyzer（quadruped_perception / terrain_analyzer）
  作用：分析深度相机或 3D 雷达点云，估计台阶、坑洞、坡面、墙面、横杆和立柱；
        给 Nav2 的点只保留高于本帧拟合地面的凸起，平地/坡面不会写入代价地图。
  输入：PointCloud2，默认优先 /camera/depth/points。
  输出：/terrain/features_stamped、/perception/obstacle_points、/diagnostics。
  注意：点云必须带有效 frame_id 和传感器到 base_link 的 TF。
        只有非零新鲜时间戳、完整缓冲区及 FLOAT32/FLOAT64 单值 x/y/z 字段的消息才会锁定来源；
        坏主话题不会阻止后续候选点云接管。当前来源只接受 Header 时间严格递增的点云，
        重复/乱序包不替换最新帧，也不刷新来源心跳；时钟回拨会开始新会话并清除地面先验。
        确认坑洞会以虚拟障碍点写入局部代价地图；无回波盲区不会被当成坑。
        地面由近场有效栅格锚定；横杆落地支柱和窄立柱分别用高度带/原始回波复核。

/vision_obstacle_detector（quadruped_perception / vision_obstacle_detector）
  作用：用 OpenCV 提取颜色、轮廓和多帧稳定证据，辅助判断比赛障碍。
  输入：Image，默认优先 /camera/image_raw。
  输出：/vision/obstacle_stamped、/vision/annotated_image（RViz 标注画面）、
        /vision/debug_mask（可选）及调试信息。
  注意：仅在 vision:=true 时启动；视觉结果不包含可靠的米制距离；断流恢复会重新累计多帧证据。
        Image 必须具有非零新鲜时间戳、合法 frame/编码/宽高/step 和完整数据；不合格候选源不锁定。
        当前来源只接受 Header 时间严格递增的图像，重复/乱序包不刷新心跳或多帧投票。
        蓝白限高杆需至少三段尺寸相近、水平对齐且间距规律的蓝色短段；单根着色细柱可提示立柱。孤立 Canny
        横边或大框不会单独输出横杆/墙，WALL 由点云确认。

/perception_fusion（quadruped_perception / perception_fusion）
  作用：按时间戳同步点云几何与视觉结果，并检查视觉框与前向通道相交，输出统一障碍信息。
  输入：/terrain/features_stamped、/vision/obstacle_stamped。
  输出：/perception/fused_obstacle、/diagnostics。
  注意：点云负责尺寸和安全判断，视觉只增强类别置信度；相机断流 0.25 s 后退化为纯点云输出。

2.2 安全决策节点

/terrain_safety_assessor（quadruped_planning / terrain_safety_assessor）
  作用：把融合障碍结果转换成 WALK、STEP、CLIMB 或 STOP，并给出速度上限。
  输入：优先 /perception/fused_obstacle；关闭视觉时使用 /terrain/features。
  输出：/terrain/navigation_safety、/terrain/navigation_mode、/terrain/speed_limit、
        /perception/front_obstacle_name。
  注意：终端约每秒打印一次正前方障碍名称、置信度、距离和高度；名称优先来自点云几何，
        可显示主斜坡、木桥引坡、T 字形台阶、限高杆、直角绕杆区、坑区和高墙。T 字台阶
        同时兼容“直接看到顶部”和“多级踏面形成阶梯趋势”两种视角。仅视觉命中
        会标明“点云未确认/待分类”，且不能覆盖已确认名称。无法由局部数据区分木桥 A/B 时
        明确写“待结构确认”。越障目标在 0.90 m 外保留低速入口接近窗口，进入交接区停车。
        当前只提供导航约束，不发送抬腿、关节或越障动作命令。比赛专名连续 3 帧一致
        才切换、连续 4 帧无障碍才清除；感知无效立即发布，不保留旧名称。融合 Header 必须
        严格递增，重复/乱序帧不刷新安全心跳，持续重发最终按感知超时处理。

/traversal_guidance（quadruped_planning / traversal_guidance）
  作用：把障碍几何转换为 Nav2 越障入口的接近、对正和 READY 交接状态。
  输入：/terrain/navigation_safety。
  输出：/traversal/guidance、/traversal/phase、/traversal/approach_pose。
  注意：入口位姿位于输入 frame（通常 base_link）的障碍前方；本节点不发送 Nav2 goal，
        不生成关节动作。POLE 由 Nav2 绕杆，不触发运动控制交接；READY 需连续 3 帧，
        具有距离/角度迟滞；输入断流输出 INVALID 并清除历史。approach_pose 仅在当前确有
        有效越障目标时发布，程序必须以 guidance 为权威有效性来源。

/navigation_speed_gate（quadruped_planning / navigation_speed_gate）
  作用：依据地形限制和导航健康状态缩放 Nav2 速度，并以雷达做极近距离急停兜底；
        数据异常、关键心跳超时或自动导航退出时立即输出零速度。
  输入：/cmd_vel_smoothed、/terrain/speed_limit、/navigation/healthy、/scan、
        /navigation/autonomy_stop。
  输出：最终标准 /cmd_vel。
  注意：它只限制已有速度，不自行生成运动指令；雷达急停距离默认 0.22 m，不负责把
        可越障目标改成绕行目标。地形限速为零时，可把 DWB 线速度不超过 0.12 m/s 且含
        yaw 的转向主导输入转换为纯 yaw 输出；输出线速度仍为零，用于换视角和返程脱困。
  转向恢复输入：/navigation/rotation_recovery（std_msgs/Bool，4 Hz 心跳）。仅自主任务拥有
        Nav2 转向的返航、探索、覆盖、回访、接近、对正和换视角阶段为 true；断流 0.8 s
        自动失效。速度门只提取最大 0.30 rad/s yaw，绝不放行 linear，全部安全守卫仍有效。

/autonomous_mission（quadruped_planning / autonomous_mission）
  作用：在未知地图中选择探索前沿；确认障碍后让 Nav2 到达入口、调用越障 Action，成功后
        记录该障碍；优先回访已知未完成项，再探索未知项，全部完成后去终点。每次只处理
        一个障碍。它负责任务编排，不生成腿部或关节命令。
  输入：/map、/traversal/guidance、/terrain/navigation_safety、
        /perception/front_obstacle_name、/global_costmap/costmap、map -> base_link TF、
        Nav2/越障 Action 结果；可选
        /autonomy/finish_pose（PoseStamped，map）覆盖默认“起点即终点”。
  输出：调用 /navigate_to_pose 和 /traverse_obstacle；发布 /autonomy/state、/autonomy/event、
        /autonomy/progress，以及 transient-local 的 /autonomy/completed_obstacles 和
        /autonomy/pending_obstacles（String 内为 count/ids/names_zh JSON）。
  进度显示：自主任务终端每 5 秒及清单变化时显示“已越过/未越过”；上述三个话题用于其他
        节点、UI 或晚启动终端读取同一账本。/autonomy/progress 是分号分隔的可读 String，
        关键字段为 state、completed、score、elapsed_seconds、budget_remaining_seconds、
        completed_ids、pending_ids；默认总预算 300 s，最后 60 s 预留返程。
  生命周期：仅随 autonomous_navigation.launch.py 存在；启动 launch 即执行，Ctrl-C 即取消退出。
  额外输出：/navigation/rotation_recovery（std_msgs/Bool）。只允许速度门从 Nav2 命令提取
        纯 yaw，不是 Twist，不开放线速度，也不绕过导航健康、外部停车或雷达急停。
  停滞时限：前沿/覆盖/入口等普通 Nav2 目标 5 s 无位姿进展即取消改选；return_home 使用
        20 s，允许 Nav2 行为树先执行 Spin/BackUp/重规划；若仍被正前障碍锁住，则先执行
        有界转向和安全换站，再重试终点。
  安全输出：/navigation/autonomy_stop（std_msgs/Bool，可靠 + transient_local）。启动发布
  false；退出先发布 true。最终仲裁器收到 true 后只锁自动导航分支；有效键盘/手柄输入
  仍可人工接管。标准优先级：人工输入 > 自动导航锁 > 自动导航输入 > 零速度。
  注意：前沿和障碍锁均来自实时地图/感知，不读取 Gazebo world 坐标；真机必须提供真实
        /traverse_obstacle 服务端。autonomous_navigation.launch.py 永远不启动仿真服务端；
        仿真替身只由 quadruped_gazebo 的独立 launch 显式启动。
  对正：确认唯一障碍后先调用 /navigate_to_pose 做同位置纯 yaw 对正，再接近入口；单次
        最多修正 0.524 rad，转后等待 0.6 s 新感知，Action 交接航向门限为 0.12 rad。
  回访：多帧语义确认后记录“障碍 map 位置 + 当时安全观察位”。若尚未完成，空闲时优先
        返回观察位并朝向障碍重新识别；近场语义退化时还必须满足实时粗类型兼容和 0.90 m
        空间门才可复用历史 ID。历史记录不能单独触发 Action；每次回访按 8/16/32/64 s
        指数退避，到达观察位但没有重新捕获也不会清零。
  去重：完成记录使用“障碍几何类别 + map 坐标”，只屏蔽 0.65 m 内的同类旧目标；不同
        类别的相邻比赛障碍仍会独立进入引导和 Action。
  成功判定：`/traverse_obstacle` 必须同时得到 ROS `SUCCEEDED` 和 Result `success=true`；随后
        节点进入 VERIFYING_TRAVERSAL_RESULT，以实时 map -> base_link 检查机体确实越过入口
        平面，并连续稳定 0.75 s。失败或 5 s 内无法证实则不计完成，障碍继续留在待办清单。
        足端接触、机身姿态、关节/驱动故障和完整离开障碍由真机 Action 服务端负责；仅仅
        接受 Goal、走到入口或播放完动作序列都不能返回 success=true。
  防卡死：Nav2 连续 5 秒没有至少 0.04 m 平移或 0.06 rad 转动就取消。前沿被障碍阻挡或
        入口守卫不通过时，交替转向 90° 并尝试经普通安全链移动 0.80 m 来换观察站。若是障碍入口，任务保留
        创建目标时已经多帧确认的语义，仅在实时点云仍落于同一 map 入口且粗类型、距离、
        横偏和航向一致时交给越障 Action；停滞后 2.35 m 内可由控制器接管最后一段低速接近。
        守卫不通过则同时冷却语义记录和空间入口；即使只有通用 STEP/WALL、尚无唯一比赛名，
        也会按 map 位置冷却并改选其他前沿/障碍，不在原观察点每 5 秒重复发送同一目标。
        越障服务端未就绪只等待 5 秒；无可用目标时补扫两圈，仍无结果便返回启动点。
  换站地图：标准 `/global_costmap/costmap` 同时包含激光与地形点云。任务只选择整条路径和
        机身净空均为已知自由格的观察站；没有候选就拒绝盲移，不发布绕过速度门的 Twist。
  近距交接：唯一障碍语义、实时点云几何、横偏及航向均通过时，1.45 m 内可直接调用
        /traverse_obstacle，避免入口前重复发送 Nav2 Goal；任一条件失败仍走普通恢复流程。
  结构判定：直角绕杆成功由 Action 结果、有效位移和稳定时间共同确认；其余障碍还要越过
        在线入口平面。任务话题和 Action 名称未因该特例改变。

2.3 SLAM 与导航监控节点

/slam_toolbox（slam_toolbox / async_slam_toolbox_node）
  作用：使用 2D 激光雷达和里程计在线建图与定位。
  输入：/scan、odom -> base_link TF。
  输出：/map、map -> odom TF 及 SLAM Toolbox 标准服务。
  注意：本节点不生成 /odom，必须由未来真机状态估计模块提供。

/nav2_readiness_monitor（slam / nav2_readiness_monitor）
  作用：校验 /scan 的 frame/角度/样本/回波和 /odom 的时间/frame/数值，再等待定位 TF
        就绪并激活 Nav2。
  输入：/scan、/odom、map -> base_link TF。
  输出：调用 /lifecycle_manager_navigation/manage_nodes，不发布运动话题。
  注意：传感器话题和生命周期服务均要求绝对 ROS 名称；frame 不带前导 `/`。

/navigation_health_monitor（slam / navigation_health_monitor）
  作用：运行中继续检查上述数据合同、里程计突跳、时间戳和 TF 是否可靠。
  输入：/scan、/odom、map -> base_link TF。
  输出：/navigation/healthy、/diagnostics。
  注意：任何关键输入断流或异常都会将健康状态置为 false；里程计跳变需连续稳定样本后恢复。
        雷达有效率必须在 (0, 1]，扫描样本数至少 2，传感器超时必须大于 0。

2.4 Nav2 节点组

/planner_server
  作用：运行 NavFnPlanner，根据 SLAM 地图和全局代价地图生成全局路径。
  选型：当前保留 NavFn；Nav2 Jazzy 没有官方 D* Lite 插件。真机阶段先用同一 rosbag
        对比官方 Smac 规划器，只有全局重规划确为瓶颈时再考虑自研增量规划器。

/controller_server
  作用：运行 DWBLocalPlanner，结合局部代价地图跟踪全局路径并产生 /cmd_vel_nav。

/smoother_server
  作用：平滑路径，减少折线和不必要转向。

/behavior_server
  作用：提供等待、后退、旋转和清图后的恢复行为。

/bt_navigator
  作用：执行 NavigateToPose 行为树，协调规划、控制、重规划和恢复。

/velocity_smoother
  作用：限制速度和加速度突变，将 /cmd_vel_nav 平滑为 /cmd_vel_smoothed。

/lifecycle_manager_navigation
  作用：统一配置、激活和关闭上述 Nav2 生命周期节点。

2.5 手柄节点（不随主导航启动）

/xbox_teleop（quadruped_teleop / xbox_teleop）
  作用：把 Xbox 手柄标准 /joy 转换为带安全解锁、急停、断流重解锁和三档限速的机身速度；
        十字键上/下启动或 Ctrl-C 本节点拥有的独立自主任务进程。
  输入：/joy（sensor_msgs/msg/Joy）。
  输出：/cmd_vel_joy（Twist）、/teleop/active（Bool）、/teleop/emergency_stop（Bool）、
        /teleop/speed_mode（String）、/teleop/autonomy_process（String：
        STOPPED/RUNNING/STOPPING/FAILED）。
  进程：上键执行 ros2 launch slam autonomous_navigation.launch.py；下键向其进程组发送
        SIGINT。只管理自己启动的 PID，不停止 Gazebo、核心 SLAM 或外部自主任务。
  注意：默认不直接发布 /cmd_vel；真机使用 twist_mux 仲裁后再进入硬件安全层与驱动。
  启动：xbox_teleop.launch.py 同时拉起外部 /joy 驱动和本节点，但不加入 slam.launch.py。

2.6 辅助节点与工具

/robot_state_publisher
  作用：根据 URDF 发布机器人固定 TF 和 robot_description。
  注意：真机已有自己的 URDF/TF 发布者时设置 robot_model:=false，避免 TF 冲突。

/rviz2
  作用：显示地图、点云、路径和障碍结果，不参与算法决策。
  注意：默认隐藏 TF/网格以保持地图清晰，视图跟随 base_link 而 Fixed Frame 仍为 map；
        白=自由、黑=占用、灰=未知，TF 可按需手动开启。
  退出诊断：Ubuntu 可能延迟显示旧崩溃报告；以报告 Date 和最新 launch.log 中 rviz2 的
  实际退出状态为准，`process has finished cleanly` 表示当前通信与算法未受影响。

perception_bag_evaluator（离线工具，不随一键启动运行）
  作用：读取 rosbag 和人工标签，统计识别准确率、召回率及连续量误差。

stack_regression（测试工具，不随一键启动运行）
  作用：在 Gazebo 中验证旋转/倒退回环、多目标、1 m 窄通道、恢复行为和资源占用。
  接口：显式 --allow-motion 后发布 /cmd_vel_teleop；订阅 /map、/scan、/odom、
        /navigation/healthy、/perception/front_obstacle_name、/traversal/guidance，并调用
        Nav2 Action；额外检查错误 READY 和 ALIGN/READY 快速往返。
  输出：reports/*.json；真机禁止运行运动阶段。

2.7 独立 Gazebo 节点（只由 quadruped_gazebo 的 launch 管理）

/robocon_clock_bridge（ros_gz_bridge / parameter_bridge）
  作用：独立发布 /clock，避免其他传感器转换阻塞所有 use_sim_time 节点。

/robocon_navigation_bridge（ros_gz_bridge / parameter_bridge）
  作用：桥接关键 /scan、/odom、/tf，并把唯一的 /cmd_vel_gazebo 送到 Gazebo 模型的
        /cmd_vel；不承载大点云。

/sim_cmd_vel_mux（quadruped_gazebo）
  作用：仅在仿真中仲裁算法 /cmd_vel、键盘 /cmd_vel_teleop 和 Xbox /cmd_vel_joy，输出
        /cmd_vel_gazebo；人工输入优先于自主锁，两路人工输入按最新有效消息选择。

/sim_keyboard_teleop（teleop_twist_keyboard，仅 GUI 仿真默认启动）
  作用：让第一条 Gazebo 命令自动提供键盘人工控制，不再要求第四条启动命令。
  输出：/cmd_vel_teleop；i/k 前后、j/l 原地旋转，其他键停车。
  注意：只属于仿真输入，不启动或关闭 SLAM、自主任务；命令仍由 sim_cmd_vel_mux 仲裁。

/sim_traverse_obstacle（仿真一次性传送 Action 替身）
  作用：在无动力学测试载体上实现 /traverse_obstacle；任务对准后把模型一次传送到障碍出口，
        限时模式下在核心清单变化后切换下一参考观察位，用于验证任务登记与继续探索；不模拟
        碰撞、步态或中间轨迹，也不拥有核心任务清单。
  输入：TraverseObstacle goal、/odom、/autonomy/completed_obstacles、Gazebo set_pose 服务；
        航向误差绝对值必须不超过 0.24 rad（普通独立后端默认 0.22 rad）。
  输出：Action feedback/Result、停止用零 Twist；限时模式额外发布标准
        /perception/fused_obstacle 和返场后的 /autonomy/finish_pose。
  生命周期：推荐随 quadruped_gazebo/robocon_field_teleport.launch.py 启动；也可在纯场地
        已运行时单独启动 sim_traversal_controller.launch.py。绝不随 slam.launch.py、
        autonomous_navigation.launch.py 或真机入口启动，不能代表真实越障。
  注意：限时融合输入只验证跨节点流程，不是 OpenCV/点云识别成绩；核心仍必须通过 Action、
        位移、入口平面和落地稳定后验才会更新 completed_obstacles。

/robocon_aux_sensor_bridge（ros_gz_bridge / parameter_bridge）
  作用：桥接 /imu/data 和 /camera/camera_info；辅助数据异常不影响导航桥。

/robocon_point_cloud_bridge（ros_gz_bridge / parameter_bridge）
  作用：将 /camera/points 独立桥接为 /camera/depth/points，并修正仿真点云 frame。
  注意：纯场地入口默认开启；三分钟闪现入口默认关闭，避免与确定性融合回归输入同时竞争。

/robocon_image_bridge（ros_gz_bridge / parameter_bridge）
  作用：把 Gazebo 424×240@15 Hz RGB 图像转换为标准 /camera/image_raw，供 OpenCV 直接使用；
        分辨率只是独立仿真的轻量档，话题类型和名称与真机合同相同。
  注意：RGB-D 光心在测试狗机头外侧并向下俯约 14°；标注输出
        /vision/annotated_image 使用 RELIABLE QoS，兼容 RViz 默认 Image 显示。

/lidar_static_tf、/camera_static_tf、/camera_optical_static_tf、/imu_static_tf
  作用：只为仿真通用机械狗补齐 base_link 到雷达、相机、光学帧和 IMU 的固定外参。
  换正式 SDF 时设置 publish_test_sensor_tf:=false，由真实模型/驱动发布外参，避免 TF 冲突。

以上节点不是核心算法节点，slam.launch.py 不会启动它们；真机运行时也不应启动。
同一 ROS 域不得重复启动 robocon_field.launch.py；必须保证 /clock 只有一个发布者。
仿真算法请在另一终端执行 `ros2 launch slam slam_sim.launch.py`。该入口不新增节点，也不
启动 Gazebo，只固定 use_sim_time=true、robot_model=false，确保传感器时间和 TF 所有权一致。
普通 slam.launch.py 也会自动探测 /clock，启动首行应显示 simulation_detected=true。
若 /scan、/odom 或 /camera/depth/points 任一路停止，地图/障碍结果会保持最后一帧或进入
“感知数据无效”；先用 `ros2 topic hz <话题>` 区分数据源断流与算法识别失败。
TF 链路检查使用 ./scripts/diagnose.sh；脚本会安全截取 tf2_echo 输出，避免诊断管道关闭被
误认为 ros2 节点崩溃。

三、标准输入接口
------------
/scan
  类型：sensor_msgs/msg/LaserScan
  用途：SLAM、Nav2 costmap、启动检查和健康监控。

/odom
  类型：nav_msgs/msg/Odometry
  配套 TF：odom -> base_link
  用途：Nav2 控制与健康监控。当前仓库不生成真实 odom；独立 Gazebo 测试载体只生成仿真 odom。

/cmd_vel、/cmd_vel_teleop、/cmd_vel_gazebo
  类型：geometry_msgs/msg/Twist
  用途：/cmd_vel 是算法/未来真机标准输出；后两者只属于 Gazebo 手动联调仲裁，不是真机接口。

/joy
  类型：sensor_msgs/msg/Joy
  用途：Xbox 手柄轴和按键输入，由外部 joy_node 发布；默认映射见 xbox.yaml。

/camera/image_raw（推荐默认）
  类型：sensor_msgs/msg/Image，推荐 bgr8/rgb8；其他常见命名由候选列表/profile 适配。

/camera/depth/points（推荐默认）
  类型：sensor_msgs/msg/PointCloud2，必须包含 x/y/z，单位 m，并有有效 Header.frame_id。

/tf、/tf_static
  类型：tf2_msgs/msg/TFMessage
  最低要求：map->odom、odom->base_link、base_link->lidar/camera/pointcloud frame。

四、感知输出字段
------------
/terrain/features
  类型：std_msgs/msg/Float32MultiArray，兼容旧 bag。
  索引：0 ground_height；1 high_z；2 obstacle_height；3 valid_points；
  4 slope_pitch_tan；5 roughness；6 frontal_obstacle_height；7 lookahead_distance；
  8 traversability；
  9 pit_depth；10 slope_roll；11 obstacle_type；12 confidence；13 width；14 clearance_height。
  新程序优先使用带 Header 的强类型话题。

/terrain/features_stamped
  类型：quadruped_interfaces/msg/TerrainFeatures
  字段：header、valid、obstacle_type、confidence、ground_height、obstacle_height、pit_depth、
  slope_pitch、slope_roll、roughness、distance、lateral_offset、width、clearance_height、valid_points。

/vision/obstacle_evidence
  类型：std_msgs/msg/Float32MultiArray
  六字段：[type, confidence, center_x, center_y, width, height]，后四项归一化为 0..1。

/vision/obstacle_stamped
  类型：quadruped_interfaces/msg/VisionObstacle，字段与上面一致并增加 header。
  类型码：0 NONE，1 POLES，2 HEIGHT_BAR，3 WALL，4 COLORED_OBSTACLE。
  有效性：图像须通过曝光/对比度/清晰度门控，并满足多帧同类比例、抖动和框 IoU。

/perception/fused_obstacle
  类型：quadruped_interfaces/msg/FusedObstacle
  类别码：0 UNKNOWN，1 CLEAR，2 STEP，3 PIT，4 WALL，5 BAR，6 POLE。
  字段：header、obstacle_type、confidence、geometry_confirmed、vision_confirmed、
  obstacle_height、pit_depth、slope_pitch、slope_roll、roughness、distance、lateral_offset、width、
  clearance_height、time_skew、valid_points。
  融合约束：点云提供米制尺度；视觉 BAR 需点云 clearance_height 支持，POLE 需点云窄宽度
  支持。视觉/几何冲突时类别保持点云结果并降低 confidence。所有类别、连续字段、视觉框
  和有效位在融合消费者处二次校验；旧/未来 Header 不得维持 perception_valid。

五、决策和速度接口
--------------
/terrain/navigation_mode，std_msgs/msg/String
  WALK：地形允许 Nav2；STEP/CLIMB：识别类别但当前必须停车；STOP：危险或数据无效。

/terrain/speed_limit，std_msgs/msg/Float32
  0..1。无地形心跳默认 0；WALK 通常 1；视觉复核和立柱绕行会限速；STEP/CLIMB/STOP 为 0。

/cmd_vel_nav、/cmd_vel_smoothed、/cmd_vel
  类型均为 geometry_msgs/msg/Twist。分别表示 Nav2 原始、平滑后和通过地形/健康/雷达
  急停检查后的最终自动导航速度。

/cmd_vel_joy，geometry_msgs/msg/Twist
  Xbox 手柄独立速度候选；LB 未安全解锁/松开、B 急停或 /joy 断流时为零；断流恢复后
  必须松开并重新按下 LB。当前没有自动接入 /cmd_vel，未来由 twist_mux 与 Nav2 仲裁，
  仲裁结果再送入真机硬件安全层与驱动。

/teleop/active、/teleop/emergency_stop、/teleop/speed_mode
  类型依次为 Bool、Bool、String，均采用 reliable + transient local，供后来启动的监控或
  仲裁节点立即取得当前使能、急停和 slow/normal/fast 档位状态。

/navigation/healthy，std_msgs/msg/Bool；/diagnostics，diagnostic_msgs/msg/DiagnosticArray。
  健康监控检查 LaserScan 厂商量程、NaN/±Inf、里程计有限性/协方差/四元数、采样时间戳、
  接收超时、TF 和位置突跳。正 Inf 表示量程内无障碍，仍是合法 LaserScan 回波。

/terrain/visual_assist_active，std_msgs/msg/Bool
  表示当前速度上限是否受稳定视觉证据限制，仅供调试和 rosbag 统计。

/terrain/navigation_safety，quadruped_interfaces/msg/NavigationSafety（跨团队首选）
  Header：感知观测时间及算法使用的 base_link 坐标系；感知超时时使用当前时间。
  模式：MODE_UNKNOWN=0、MODE_WALK=1、MODE_STEP=2、MODE_CLIMB=3、MODE_STOP=4。
  有效性：perception_valid、visual_assist_active；无效或断流时 mode=STOP、speed_limit=0。
  几何：obstacle_type、confidence、obstacle_height、pit_depth、slope_pitch、slope_roll、
  roughness、distance、lateral_offset、width、clearance_height、valid_points。障碍码与
  FusedObstacle 一致；lateral_offset 在 base_link 中左正右负，用于入口对正。
  语义：同一条消息给出一个原子只读快照，供未来运动/越障模块做输入校验；它不是动作、
  关节、足端或控制器切换命令。消费者必须检查 perception_valid、Header 新鲜度和 mode。

/traversal/guidance，quadruped_interfaces/msg/TraversalGuidance（越障交接首选）
  阶段：INVALID、CLEAR、APPROACH、ALIGN、READY。
  关键字段：header、phase、obstacle_type、perception_valid、traversal_required、
  ready_for_handoff、confidence、distance、lateral_offset、heading_error、approach_x、
  approach_y、approach_yaw、speed_limit。
  语义：APPROACH/ALIGN 表示 Nav2 应到达障碍前方入口并对正；READY 表示可以由未来运动
  控制器申请接管。它不是“越障已经完成”，也不是关节命令。

/traversal/approach_pose，geometry_msgs/msg/PoseStamped
  相对入口建议，frame 通常为 base_link；autonomous_mission 在接收时转换到 map 后再发送
  NavigateToPose。不得把 pose 直接放到实体障碍后方。

/traversal/phase，std_msgs/msg/String
  人类调试速查，值为 INVALID/CLEAR/APPROACH/ALIGN/READY；程序应优先使用强类型 guidance。

/traverse_obstacle，quadruped_interfaces/action/TraverseObstacle（运动组实现的交接合同）
  Goal：obstacle_type（STEP=2、PIT=3、WALL=4、BAR=5、SLOPE=7）、confidence、distance、
  lateral_offset、heading_error；坡面不会与 CLEAR 共用动作编码。
  Feedback：PREPARING/TRAVERSING/STABILIZING、progress、message。
  Result：success、message；只有真实控制器确认稳定完成跨越后才能令 success=true。

/autonomy/state、/autonomy/event，std_msgs/msg/String
  关键 state：WAITING_FOR_INPUTS、EXPLORING、COVERAGE_EXPLORING、
  SEEKING_PENDING_OBSTACLE、ALIGNING_OBSTACLE、HANDOFF、TRAVERSING、
  SEARCHING_MISSING_OBSTACLES、RETURNING_TO_FINISH、RECOVERY、COMPLETED；event 是低频原因。
  节点没有键盘或 toggle 服务；进程生命周期就是自主功能的启停边界。

/autonomy/completed_obstacles、/autonomy/pending_obstacles，std_msgs/msg/String
  可靠 + transient_local 的任务清单；data 为 JSON：count、ids、names_zh。只有
  TraverseObstacle Result.success=true 才从 pending 移到 completed，感知识别本身不计完成。

/autonomy/finish_pose，geometry_msgs/msg/PoseStamped（可选输入）
  正式终点，必须是 map frame 且数值/四元数有效；未发布时自动使用任务启动点作为终点。

六、设备替换合同
------------
驱动只需发布正确消息和 TF，不要求算法认识厂商品牌。优先保持默认话题；否则：

  ros2 launch slam slam.launch.py sensor_profile:=realsense_d400

或：

  ros2 launch slam slam.launch.py scan_topic:=/x/scan odom_topic:=/x/odom \
    camera_topic:=/x/image_raw point_cloud_topic:=/x/points

若 3D 雷达只有 PointCloud2，当前 2D SLAM 仍需用厂家工具或 pointcloud_to_laserscan 生成
LaserScan。相机和点云最好使用同一时间源；硬件同步优先，软件时间差应稳定低于 0.10 s。

未来硬件/状态估计团队必须提供：/scan、/odom、odom->base_link、传感器固定 TF，以及实际
相机和点云话题；未来底盘/运动团队必须订阅最终 /cmd_vel。真机负责发布自身 URDF/TF 时，
启动本项目须设置 robot_model:=false。首次接入先只检查硬件输入：

  ./scripts/check_integration.sh --inputs-only \
    --image /实际图像话题 --points /实际点云话题

它会在 5 秒限时内实际读取 LaserScan、Odometry、Image、PointCloud2，检查消息类型和
header.frame_id，并验证 base_link 到每个传感器及 odom->base_link 的 TF。只有这一层通过，
才启动算法并执行完整检查：

  ./scripts/check_integration.sh \
    --image /实际图像话题 --points /实际点云话题

完整模式继续检查 map->base_link、算法输出、/cmd_vel 消费者，并把未接真实
/traverse_obstacle 服务端作为警告；正式联调动作控制时增加 --require-traverse-server 将其
升级为失败。无视觉机器可用 --skip-vision，但 OpenCV/点云分类会失效。脚本只读，不启动、
控制或发送速度；返回非零表示对接合同未满足。旧的两个位置参数仍兼容，完整参数见 --help。
VS Code 中同样提供任务“ROS: check robot integration contract”。

profile 与 launch 覆盖必须是 / 开头的绝对话题。内部固定使用标准消息类型，frame 默认遵循
map -> odom -> base_link -> sensor_frame；若已有机器人使用其他 frame，可在检查脚本用
--map-frame/--odom-frame/--base-frame 描述现状，但正式接入仍推荐在机器人适配层对齐标准名称。

七、明确不存在的接口
----------------
当前已有 TraverseObstacle Action 定义、客户端和独立仿真流程服务端，但没有真实运动服务端、
CrossingCommand/CrossingStatus、hardware/status、joint trajectory、ros2_control controller、
模拟 SDK、正式比赛状态机或故障注入控制接口。未来真机模块应单独实现 Action 服务端，
不能让感知话题直接驱动关节。

Isaac Lab 训练/策略接口同样尚未定义。应在真机关节、状态估计和执行器合同确定后，再冻结
观测向量、动作向量、字段顺序、单位、坐标系、归一化和控制周期；当前阶段不预设 ROS 话题，
避免训练接口反向污染已经稳定的 SLAM/Nav2/感知通信合同。

八、移植时的通信所有权
------------------
本次采用完整算法移植：目标机器人没有 SLAM/Nav2，本项目负责 SLAM Toolbox、Nav2、OpenCV、
点云、融合和任务层；目标机器人负责传感器驱动、状态估计、TF、运动控制与硬件安全。最容易
出错的不是话题名称，而是同一接口被两个模块同时拥有：

| 接口 | 唯一生产者 | 本算法角色 |
|---|---|---|
| `/scan`、Image、PointCloud2 | 目标机器人的传感器驱动 | 只订阅，可用 remap/profile 对齐 |
| `/odom`、`odom -> base_link` | 目标机器人的状态估计 | 只订阅，算法不得重复发布 |
| `map -> odom`、`/map` | 本项目 SLAM Toolbox | 目标端不得再启动另一套 SLAM |
| `base_link -> sensor_frame` | 目标机器人的 URDF/静态 TF | 移植时 `robot_model:=false` |
| `/cmd_vel` | 目标 twist_mux/安全层，或本项目 speed gate 二选一 | 已有仲裁器时 `speed_gate:=false` |
| `/navigate_to_pose` | 本项目 Nav2 bt_navigator | autonomous_mission 为客户端 |
| `/traverse_obstacle` | 真机运动/越障控制器 | 本项目只提供 Action 客户端与合同 |

必须迁移 quadruped_interfaces、quadruped_description、quadruped_perception、
quadruped_planning、quadruped_bringup、slam 六个包。传感器、里程计和 TF 启动后执行：

  ros2 launch slam slam.launch.py robot_model:=false \
    scan_topic:=/实际scan odom_topic:=/实际odom \
    camera_topic:=/实际image point_cloud_topic:=/实际points

该入口同时启动 SLAM、Nav2 和感知算法。若目标已有 twist_mux/底盘安全层，在命令中增加
`speed_gate:=false`，让目标安全层消费 `/terrain/navigation_safety` 并独占最终 `/cmd_vel`；
这不表示复用目标 SLAM/Nav2。目标端应把 `perception_valid=false` 或数据超时视为停车条件，
不能把 STEP/CLIMB/READY 直接解释成关节动作。

若采用本项目完整速度链，所有权必须是：Nav2 controller -> `/cmd_vel_nav` -> velocity
smoother -> `/cmd_vel_smoothed` -> navigation_speed_gate -> `/cmd_vel`。迁移完成后执行
`ros2 topic info /cmd_vel --verbose`，确认不存在第二个 Nav2、键盘或旧安全节点直接发布同名
最终速度。消息/Action 接口版本也必须一致；同一 ROS_DOMAIN_ID 中不得出现两个不同构建的
`quadruped_interfaces`。

8.1 真机联调时观察哪些接口

第一阶段只看输入：`/scan`、`/odom`、Image、PointCloud2，以及
`odom -> base_link -> sensor_frame`；此时电机禁用。第二阶段启动完整算法但令
`nav2_enabled:=false speed_gate:=false`，观察 `/map`、`map -> base_link`、
`/perception/fused_obstacle`、`/perception/front_obstacle_name`、
`/terrain/navigation_safety` 和 `/traversal/guidance`。第三阶段启用 Nav2，先只观察全局路径、
局部代价地图和 `/cmd_vel_smoothed`。最后确认 `/cmd_vel` 只有一个发布/仲裁链且有真实控制
订阅者，才允许低速接电机；越障阶段另检查 `/traverse_obstacle`、`/autonomy/state` 和两份
障碍清单。各阶段命令与通过标准见 instruction.txt 第十节第 6 项。
